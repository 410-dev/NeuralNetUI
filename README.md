# Neural Chat

`llm-chat-ui.html`의 디자인 언어를 이어 만든 다중 서버 채팅 UI입니다. OpenAI API와 LM Studio 드라이버, 서버별 모델 설정, 우선순위 라우팅을 지원하며 Next.js 프론트엔드와 스트리밍 프록시 백엔드를 한 프로세스에서 실행합니다.

## 세부 컴퓨터 권한·사용자 저장소 (3.0.0 beta 3)

- 부분 신뢰 설정을 위험도 5개 전역 스위치에서 27개 하위 작업의 별도 권한 행렬로 교체했습니다. 기본 하네스 화면에는 요약과 **권한 행렬 열기**만 표시됩니다.
- 파일 검색·정보 확인·읽기·복사·쓰기·이름 변경·이동·삭제를 각각 제어하며, 덮어쓰기와 재귀 삭제는 더 보수적인 별도 행입니다. 업로드, 프로세스 시작·조회·종료, 화면 캡처도 독립적으로 선택합니다.
- PowerShell과 Bash는 서로 분리하며, 독립 명령 분석기가 산출한 위험도 1~5를 셸별로 자동 허용하거나 매번 확인하도록 설정할 수 있습니다.
- 각 행은 **자동 허용** 또는 **매번 확인** 중 하나만 선택합니다. 일괄 자동 허용과 일괄 확인 단축 버튼, 모바일용 전체 화면 모달, 키보드 포커스 트랩을 포함합니다.
- beta 2의 위험도 설정은 처음 읽을 때 같은 위험도에 해당하는 세부 작업으로 정확히 변환되어 기존 승인 범위를 임의로 넓히지 않습니다. 알 수 없는 작업이나 셸은 항상 확인합니다.
- 화면 캡처와 채팅 이미지는 base64 문자열로 보관하지 않고 사용자별 파일 저장소에 기록한 뒤 인증된 URL로 표시합니다. LM Studio 네이티브 경로에는 이미지 파일 경로를 직접 넘기며, OpenAI 호환 HTTP에만 전송 직전 호환 형식으로 변환합니다.
- 사이드바 검색 아래의 **저장소 관리**에서 본인의 첨부 파일·도구 스크린샷, 사용량과 할당량을 확인하고 다운로드할 수 있습니다. 저장된 채팅에서 참조 중인 파일은 대화가 깨지지 않도록 직접 삭제할 수 없습니다.
- 신규 사용자의 기본 할당량은 512MB이며 관리자가 1MB~10TB 범위에서 MB/GB 단위로 바꿀 수 있습니다. 사용자 목록은 계정별 사용/할당량과 전체 사용/할당 합계를 표시하고, 업로드 예약과 할당량 축소는 원자적으로 검사합니다.
- 사용자별 관리 모달은 표시 이름, 권한, 저장소 할당량을 한곳에서 관리합니다. 관리자는 수사 대응용으로 모든 분기를 포함한 개별·전체 채팅 기록 ZIP과 개별·전체 미디어를 탐색·다운로드할 수 있으며, 접근·내보내기는 감사 로그에 남습니다.
- Windows 패키지 이름: `installer/output/NeuralNetUI-3.0.0-beta.3-x64.msi`.

검증 내용은 `docs/audits/2026-09-13-release-3.0.0-beta.3.md`에 기록했습니다.

## 브라우저 컨텍스트 안정화 (3.0.0 beta 2)

- 이전 추론의 실제 토큰 사용량에 이후 브라우저 도구 호출·결과 증가분을 더해 다음 요청 크기를 계산합니다. 도넛이 70% 압축 임계값 아래였더라도 큰 도구 결과가 추가되면 전송 전에 다시 판단합니다.
- 브라우저 페이지 스냅샷은 본문뿐 아니라 전체 직렬화 결과도 제한합니다. 요소 레이블과 긴 URL이 텍스트 제한을 우회할 수 없습니다.
- 전체 페이지 스크린샷은 최대 1,440×1,600픽셀로 제한하고 잘림 여부와 페이지 높이를 반환합니다. 모델은 이어지는 영역을 스크롤해 나누어 확인할 수 있습니다.
- 스크린샷은 고정값 대신 픽셀 기반의 보수적인 비전 토큰 추정치를 사용합니다. 아직 다음 추론이 소비하지 않은 값은 도넛의 도구 사용량에도 반영됩니다.
- 도구 라운드 압축은 가장 최근의 도구 요청과 관찰 결과를 보존합니다. LM Studio가 `exceed_context_size_error` 400을 반환하면 서버의 실제 요청·컨텍스트 토큰 수로 추정치를 보정하고 안전한 압축 후 한정 재시도합니다.
- 자동 축약으로도 95% 안전 한도 아래로 줄일 수 없으면 원시 서버 오류 대신 실제 토큰 수와 페이지 분할 방법을 포함한 안정적인 오류를 반환합니다.
- Windows 패키지 이름: `installer/output/NeuralNetUI-3.0.0-beta.2-x64.msi`.

## Superadmin 호스트 컴퓨터 도구 (3.0.0 beta 1)

- 컨테이너 밖에서 실행되는 NeuralNetUI에 Superadmin 전용 **호스트 컴퓨터** 에이전트 도구를 추가했습니다. 실험적 기능에서 하나의 스위치로 켜고, 각 채팅의 도구 메뉴에서 사용할 수 있습니다.
- 파일 검색·메타데이터 확인·읽기·쓰기·복사·이름 변경·이동·영구 삭제, `temp.hysong.dev` 임시 업로드, PowerShell/Bash, 현재 화면 캡처를 지원합니다.
- 백그라운드 프로그램은 대화별로 PID와 이름을 보관합니다. 같은 대화에서 목록을 확인하고, 그 도구가 시작한 정확한 PID만 종료할 수 있습니다.
- 하네스 설정에서 **완전 신뢰**, **부분 신뢰**, **신뢰 안 함**을 선택합니다. 부분 신뢰는 별도 모달에서 하위 작업 및 PowerShell/Bash 위험도별 자동 허용 여부를 선택합니다. 기본값은 모든 작업을 확인하는 신뢰 안 함입니다.
- PowerShell/Bash는 채팅 이력을 전혀 포함하지 않는 별도 모델 요청으로 최고 위험 효과를 분류하고, 실제 경로·파일·프로그램·목적지를 포함한 사용자 언어 설명을 생성합니다. 분석 실패나 난독화는 5단계로 처리합니다.
- 확인이 필요한 작업은 실행 전에 위험도와 해석, 전체 인수를 보여 주며 **허용**, **거부**, **거부 후 다른 작업 지시** 중 하나를 선택할 수 있습니다.
- Windows 서비스 설치본의 화면 캡처는 로그인한 사용자의 트레이 프로세스와 명명 파이프로 연결해, 서비스 세션이 아닌 실제 대화형 데스크톱을 캡처합니다.
- LM Studio의 `prompt_processing` 퍼센트는 짧은 토큰 공백에 가려지지 않습니다. 서버가 30초 응답 타임아웃 기준을 실제로 넘긴 경우에만 서버 응답 대기 상태로 전환합니다.
- Windows 패키지 이름: `installer/output/NeuralNetUI-3.0.0-beta.1-x64.msi`.

검증 내용은 `docs/audits/2026-09-13-release-3.0.0-beta.1.md`에 기록했습니다.

## 진행률·컨텍스트·브라우저 수명 개선 (2.2.0 beta 3)

- LM Studio에서 도구 실행 뒤 다음 추론을 준비할 때도 실제 `prompt_processing` 퍼센트가 도구 폴드 바로 아래에 계속 표시됩니다.
- 컨텍스트 압축 중에는 압축 모델의 추론과 현재까지 작성된 요약이 Thinking과 같은 펼침 폴드에서 실시간으로 보입니다.
- 컨텍스트 도넛은 도구 호출과 도구 결과를 별도 사용량으로 표시하며, 실행 중 압축이 시작되면 압축 이전 기록을 즉시 제외하고 새 요약 기준으로 다시 계산합니다.
- 공유 브라우저 탭은 응답이 끝나거나 일정 시간이 지났다는 이유로 자동 종료되지 않습니다. 사용자가 탭을 닫거나 모델이 명시적인 닫기 동작을 실행할 때까지 같은 대화의 다음 응답에서도 유지됩니다.

## 멀티탭 공유 브라우저와 컴팩트 채팅 (2.2.0 beta 2)

- 실험적 브라우저 도구는 데스크톱 환경에서 실제 화면이 있는 Chromium 세션으로 실행됩니다. 디스플레이가 없는 서버에서는 안전하게 헤드리스 모드로 대체됩니다.
- 브라우저 모드를 켜면 채팅 상단에 화면 보기 버튼이 나타납니다. 버튼을 누르면 채팅과 브라우저가 스플릿 뷰로 열리고, 주소 이동·뒤로/앞으로·새로고침·클릭·드래그·스크롤·키 입력을 사용자가 직접 수행할 수 있습니다.
- 스플릿 뷰 한 세션에서 여러 탭을 열고 전환하거나 닫을 수 있습니다. 모델도 탭 목록의 제목·URL·레이블·노트를 조회하고, 탭을 열고 닫으며 용도에 맞게 레이블과 노트를 관리합니다.
- 관리자는 하네스 설정에서 브라우저 세션당 최대 탭 수(1~20)와 다중 선택 도구가 한 번에 물을 수 있는 질문 수(1~10)를 정합니다. 기존 설정에는 각각 8개와 3개가 기본값으로 적용됩니다.
- 연속된 추론·도구 폴드는 더 촘촘하게 배치하고, 본문과 기술 폴드 사이는 구분이 남도록 조금 더 여유를 둡니다. 제출된 다중 선택 답변은 일반 사용자 메시지와 같은 우측 기준선에 정렬됩니다.
- 모델이 CAPTCHA나 로그인처럼 사람의 조작이 필요한 단계에서 사용자에게 브라우저를 넘기면 화면이 자동으로 열립니다. 사용자가 조작을 마친 뒤 **상호작용 완료**를 누르면 같은 세션을 모델이 이어서 사용합니다.
- 브라우저 프레임과 조작 API는 로그인 사용자와 대화 소유권을 확인하며, 기존 공개 주소 제한과 서브리소스 차단을 그대로 적용합니다.
- Windows 패키지: `installer/output/NeuralNetUI-2.2.0-beta.2-x64.msi`.

검증 내용은 `docs/audits/2026-09-13-release-2.2.0-beta.2.md`에 기록했습니다.

## 설정 범위 정리 (2.1.7)

- 관리자는 모양 설정에서 로그인 화면 액센트 색상을 별도로 지정합니다. 이 색상은 로그인 화면에만 모두에게 같이 적용되며, 계정별 액센트 색상은 로그인 후에 적용됩니다.
- 모델 선택 창과 추론 수준 선택 창에 관리자용 “전체 적용”을 추가했습니다. 각각 해당 항목만 모든 계정에 기본값으로 기록하며, 상대방의 다른 설정은 그대로 둡니다.
- 일반 사용자는 서빙 모델도 기본값으로 선택할 수 있지만, 서빙 모델의 시스템 프롬프트와 추론 템플릿 같은 설정은 변경할 수 없습니다. 직접 관리하려면 별칭(커스텀) 모델을 만들면 됩니다. 서버도 동일하게 차단합니다.

## 기록 표시 개선 (2.1.6)

- 앱 전체의 생각 아이콘을 단순한 전구로 통일했습니다.
- 생각 기록은 도구 기록처럼 들여쓰기와 왼쪽 실선 없이 표시하며, 접힌 화살표는 오른쪽을 향합니다.
- 채팅 시작 후 임시 채팅 버튼 오른쪽의 눈 아이콘으로 도구·사고 기록을 즉시 숨기거나 복원합니다. 펼침 상태와 원본 기록은 보존하며, 숨김 설정은 현재 앱 세션에서 대화별로 유지됩니다. 선택형 질문과 제출한 답변은 계속 표시됩니다.
- 도구 메뉴의 마지막 항목은 현재 시간 → 현재 위치 → 브라우저 → 다중 선택 순서입니다. 브라우저 항목은 기존 실험적 설정이 켜진 경우에 표시됩니다.
- Windows 패키지: `installer/output/NeuralNetUI-2.1.6-x64.msi`.

## 2.1.5

- 임시 채팅은 배경 액센트만 회색으로 바뀌며, 메인 화면에 “안녕하세요, 여행자”와 “채팅이 저장되지 않습니다”를 표시합니다. 대화 시작 전에는 일반 채팅으로 돌아갈 수 있고, 시작 후에는 채팅을 저장할 수 있습니다.
- 새 채팅 URL은 `/`이며 실제 저장 후에만 채팅 ID가 붙습니다.
- 모델 선택 목록의 아이콘을 제거하고 체크 표시를 세로 중앙에 맞췄습니다.
- 메시지 입력란에 텍스트를 붙여넣으면 그대로 입력되고, 이미지를 붙여넣으면 첨부됩니다.
- 모양 설정에서 7개 시간대별 환영 문구 5개를 현재 언어에 맞게 편집할 수 있습니다. `{name}`은 이름으로 대체되며, 빈 문구는 기본값을 사용합니다. 메인 화면을 열 때마다 직전 문구를 제외하고 무작위로 고릅니다.
- 표시 이름은 계정 설정의 별도 그룹에서 변경합니다. 일반 사용자도 자신의 표시 이름을 변경할 수 있습니다.


## 진행률과 컨텍스트 표시 (2.1.1)

- 모양 → LM Studio 진행률에서 상태 메시지, 퍼센트, 도넛, 둘 다를 선택합니다.
- LM Studio 드라이버는 전용 SDK로 모델 로드와 프롬프트 처리 진행률을 받습니다. 연결별 인증과 모델 상주 제한을 유지하며, 시작한 추론을 자동 재전송하지 않습니다.
- OpenAI 호환 연결은 기본적으로 표준 채팅 API를 사용합니다. 관리자의 실험적 기능 → OpenAI 호환 연결 진행률을 켜면 같은 서버가 LM Studio인지 확인한 뒤 전용 연동을 시도합니다. Ollama/vLLM 등에서 제공하지 않는 진행률은 미지원으로 표시합니다. 토큰 사용량을 처리 퍼센트로 환산하지 않습니다.
- SDK 1.5.0이 표현하지 못하는 세부 추론 강도(low/medium/high 등), 이전 reasoning 별도 전송, SDK를 지원하지 않는 서버는 기존 Chat Completions 경로를 유지하며 프롬프트 진행률은 미지원입니다. Fast/Thinking 전용 경로와 기존 도구 호출은 지원합니다.
- 컨텍스트 도넛은 현재 대화와 작성 중 입력의 추정치를 표시합니다. 클릭하면 입력·응답·추론을 구분하고, ‘생각 기록 기억하기’에 따라 추론 사용량이 즉시 바뀝니다. 실제 요청에는 컨텍스트 정리가 추가 적용될 수 있습니다.


## 메시지 큐 레이아웃과 압축 후 사용량 (2.1.4.1)

- 대기 중인 메시지·첨부·업로드 중 표시가 있으면 컴포저가 알약 모양을 유지하지 못해 테두리가 깨졌습니다. 자기 줄을 차지하는 요소가 하나라도 있으면 이제 둥근 사각형 형태로 전환합니다.
- 컨텍스트 압축 후에도 사용량 도넛이 줄지 않았습니다. 압축 요약이 이전 대화를 대신한다는 사실을 반영하지 않고 원문 전체를 계속 합산했기 때문입니다. 이제 가장 최근 압축을 기준으로 그 이전 대화를 요약 토큰으로 대체해 계산하고, 세부 내역에 **압축 요약** 항목이 표시됩니다.
- MSI 참고: Windows Installer는 버전의 네 번째 자리를 비교에 사용하지 않습니다. 2.1.4 → 2.1.4.1이 같은 버전으로 취급되므로 `AllowSameVersionUpgrades`를 켜서 기존 설치본을 교체하도록 했습니다.

## 순차 출력과 컨텍스트 압축 수정 (2.1.4)

모델 출력이 일어난 순서대로 표시되고, 컨텍스트 압축이 실제로 임계점에서 동작합니다.

- 추론, 응답 본문, 도구 호출, 컨텍스트 압축이 **일어난 순서대로** 표시됩니다. 도구 호출 뒤에 나온 본문은 도구 섹션 아래에 놓이고, 한 응답에 추론 블록이 여러 개 나타날 수 있습니다. 각 단계는 자체 폴딩과 자체 소요 시간을 가집니다.
- 컨텍스트 압축은 상태 줄이 아니라 응답의 한 단계로 표시됩니다. 추론 블록과 같은 모양으로 접히며, 안에는 최대 두 개의 소형 창이 들어갑니다: 압축 모델의 사고(사고가 켜져 있을 때)와 맥락으로 유지되는 요약. 압축이 진행 중이면 그 자리에서 바로 보이고, 상태 줄에는 중복 표시하지 않습니다.
- 메시지를 **보내는 시점**에 임계점 초과를 확인합니다. 이전에는 구조적 추정값만 사용해, 화면이 89%를 표시하는 상태에서도 압축 없이 요청이 전송됐습니다. 이제 화면과 같은 측정값을 함께 사용하며, 둘 중 큰 값으로 판단합니다.
- **출력 중**에도 임계점을 넘으면 출력을 멈추고 압축한 뒤 재개합니다. 압축 직후에는 이전 측정값을 버리므로, 압축된 요청이 곧바로 다시 압축을 유발하지 않습니다.
- `%COMPRESSED%`·`%USER_PROMPT%` 설명은 재개 프롬프트 편집 창 안에 부연설명으로 표시됩니다.
- 이전 형식으로 저장된 메시지는 추론 → 도구 → 본문 순서로 그대로 표시됩니다.

검증: `npm test`, `npx tsc --noEmit`, `npm run build`, 임시 데이터 디렉터리와 모의 모델로 전송 시 압축·출력 중 압축·재개 한도·압축 불필요 네 가지 경로 확인.

## 드라이버 지원 범위 표시 (2.1.2)

- 응답 중에 표시되던 **진행률 미지원** 문구를 없앴습니다. 진행률을 제공하지 않는 서버에서는 진행률만 표시되지 않습니다.
- 대신 **연결 → 드라이버** 목록의 각 항목에 정보 아이콘이 있고, 여기에 마우스를 올리면 그 드라이버가 지원하는 기능과 지원하지 않는 기능을 표로 보여 줍니다. 모델 목록 자동 감지, 모델 로드·언로드·상주 관리, 로드·프롬프트 진행률, 추론 강도 단계 전달, 이전 생각 기록 전송 다섯 항목을 지원·제한적·미지원으로 구분하고, 제한적인 항목은 그 조건까지 함께 설명합니다. OpenAI 호환 연결의 진행률은 실험적 기능 스위치 상태에 따라 달라집니다.
- 설정 사이드바의 **모델** 항목이 신경망 마크를 사용합니다.
- 신경망 마크의 노드 간격을 넓히고 노드를 작게 하여, 원들이 붙어 육각형처럼 보이던 문제를 고쳤습니다. 파비콘도 같은 형태를 사용합니다.

검증: `npm test`, `npx tsc --noEmit`, `npm run build`, 임시 데이터 디렉터리로 실제 앱을 띄워 드라이버 정보 표와 마크를 확인.

## 임시 채팅과 시간대 인사말 (2.1.0)

- 채팅 화면 오른쪽 위에 **임시 채팅** 버튼이 있습니다. 누르면 새 임시 채팅이 시작되고, 그 대화는 채팅 기록과 검색에 나타나지 않습니다. 같은 자리의 **이 채팅 저장** 버튼을 누르면 일반 채팅이 되며, 하네스의 제목 설정에 따라 첫 요청(설정이 "응답 전"이면 요청만) 또는 첫 요청과 응답으로 제목을 생성합니다.
- 임시 채팅은 다른 채팅으로 이동하거나 새 채팅을 시작하면 삭제됩니다. 스트리밍이 진행 중인 임시 채팅은 다른 탭에서 정리되지 않습니다. 스트리밍을 위해 서버에 임시로 저장되며, 저장하지 않으면 남지 않습니다.
- 모델 아이콘이 신경망 형태의 마크로 바뀌었습니다. 모델 목록, 채팅의 모델 선택 창, 파비콘이 같은 마크를 사용합니다.
- 파비콘을 추가했습니다.
- 환영 메시지가 이른 새벽·아침·점심·오후·저녁·밤·늦은 밤 7개 시간대별로 각각 5종씩 준비되어 있고, 날짜에 따라 순환합니다. 탭을 열어 둔 동안에는 문구가 바뀌지 않습니다.
- 좁은 화면에서는 환영 메시지가 화면 폭의 70% 안에서 줄바꿈되며, 한국어는 단어 단위로만 줄이 나뉩니다.
- 모바일에서 화면을 아래로 당겨도 브라우저 새로고침이 일어나지 않습니다.
- 추론 강도 선택 창이 화면을 넘어가지 않도록 높이를 제한하고 내부에서 스크롤합니다.
- **모양** 설정에 추론 강도 설명 항목이 있습니다. 표시 여부를 켜고 끌 수 있고, Fast·Thinking·Minimal·Low·Medium·High·Extra High·Max 각각의 문구를 직접 바꿀 수 있습니다. 비워 두면 기본 문구를 사용합니다.
- "이전 Reasoning 전송"이 **생각 기록 기억하기**로 바뀌었습니다.
- 사이드바 하단 프로필은 이름 첫 글자 대신 사람 아이콘을 사용합니다.
- 하네스 설정의 **응답 길이**에서 응답 최대 토큰을 설정합니다. 기본값 0은 제한 없음으로, 남은 컨텍스트 공간을 모두 응답에 사용할 수 있습니다. 값을 지정하면 그 값과 남은 공간 중 작은 쪽이 상한이 됩니다. 이전에는 4096 토큰으로 고정 제한되어 긴 응답이 끊겼습니다.
- 설정 패널의 저장 버튼은 변경 사항이 있을 때만 활성화되고, 변경 사항이 없으면 취소 버튼이 **닫기**로 바뀝니다.
- Windows에서 로그인 시 트레이만 조용히 시작하고 웹브라우저는 열지 않습니다. Web UI는 시작 메뉴의 **NeuralNetUI** 또는 트레이 아이콘으로 엽니다. 설치 직후에는 한 번 열립니다.

검증: `npm test`, `npx tsc --noEmit`, `npm run build`, 임시 데이터 디렉터리와 모의 모델 서버로 실제 앱을 띄워 임시 채팅 생성·저장·폐기까지 확인.

## 2.0 디자인 언어 (2.0.0)

인터페이스 전체를 알약 형태 컨트롤, 무채색 텍스트, 사용자가 고르는 액센트 색상으로 다시 구성했습니다. 모델·설정·대화 데이터와 하네스 동작은 그대로입니다.

- 버튼과 입력 필드, 드롭다운 트리거는 모두 완전한 알약 형태이며, 컨테이너와 여러 줄 입력은 더 큰 코너 반경을 사용합니다. 숫자 입력의 증감 화살표는 제거했습니다.
- 모든 드롭다운은 모델 선택 창과 같은 커스텀 컴포넌트를 사용합니다. 키보드(방향키·Home·End·Enter·Esc)와 스크린 리더를 지원하고, 열고 닫을 때 모두 애니메이션이 적용되며 화면 아래쪽에서는 위로 열립니다.
- 표면과 텍스트, 입력 필드는 흰색과 회색만 사용합니다. 색은 액센트(상호작용·선택 상태)와 오류·성공 신호에만 남겨 두었습니다.
- 아이콘은 배경판 없이 흰색 선으로만 그립니다. 아이콘 버튼은 배경 대신 색과 미세한 확대로 hover를 표시합니다.
- **모양** 설정에서 액센트 색상을 6가지 팔레트 또는 커스텀 HEX로 고를 수 있습니다. 설정 창에서 고르는 즉시 미리보기가 적용되고, 취소하면 저장된 색으로 돌아갑니다.
- **모양** 설정에 응답 표시 옵션을 추가했습니다. 표시 방식은 기본 또는 부드러운 페이드, 표시 속도는 전부 표시 또는 프레임당 정해진 글자 수만 내보내는 일정한 속도(1~24자)입니다. 두 옵션 모두 모델에 전달되는 내용이나 저장된 대화를 바꾸지 않습니다.
- 메인 화면 컴포저는 기본적으로 모든 컴포넌트가 한 줄에 놓인 알약입니다. 본문이 컨트롤 사이에 들어가지 못할 만큼 길어지면 둥근 사각형으로 탄성 있게 늘어나며 텍스트가 첫 줄을 차지하고 컴포넌트가 아래로 내려갑니다.
- 사이드바는 로고와 이름을 제거하고 아이콘 하나만 남겼으며, 접고 펼칠 때 폭이 탄성 있게 움직입니다. 프로필 진입점 아이콘은 톱니바퀴로 바꿨고, 메인 화면 인사말의 아이콘은 제거했습니다.
- 모델 드롭다운에서 모델 관리 항목을 제거했습니다. 기본으로 사용과 언로드는 각각 독립된 알약 버튼이 되어 두 버튼이 함께 있어도 모서리가 어긋나지 않습니다.
- 추론 수준 설정은 이름 변경과 삭제가 가능한 커스텀 템플릿만 편집 목록에 표시합니다. 기본 제공 Native 수준은 채팅의 추론 선택 창에서만 제공됩니다.
- 컴포저 입력 안내 문구는 **보낼 메시지**입니다.
- 좁은 화면에서는 컨트롤 옆에 쓸 만한 입력 폭이 남지 않으므로 컴포저가 처음부터 늘어난 형태로 표시됩니다. 메인 화면의 좌우 여백도 좁은 화면 값을 따릅니다.
- 관리자 설정에 **실험적 기능** 탭이 있습니다. 여기서 브라우저 도구를 켜야 메인 화면과 채팅 화면의 도구 메뉴에 나타나며, 꺼져 있으면 클라이언트가 요청해도 서버가 브라우저 도구를 제공하지 않습니다.

검증: `npm test`, `npx tsc --noEmit`, `npm run build`, 임시 데이터 디렉터리와 모의 모델 서버로 실제 앱을 띄워 브라우저에서 확인.

## 하네스 설정과 사이드바 UI 정리 (1.9.1)

관리자 설정의 **하네스 설정** 탭과 메인 화면 사이드바를 사용자 친화적으로 다듬었습니다. 기능과 저장 값은 그대로입니다.

- 하네스 설정의 모든 구역이 다른 설정 탭과 같은 아이콘·제목·설명 머리글을 사용합니다.
- 컨텍스트 처리 방식(Rolling / Compacting)과 제목 생성 시점은 드롭다운 대신 아이콘과 한 줄 설명이 있는 선택 카드로 고릅니다.
- 압축 시작 임계값은 현재 값이 옆에 표시되는 슬라이더로 조절합니다.
- 모드에 따라 나타나는 하위 설정은 선택 카드 아래의 한 묶음 안에 모입니다. 추론 강도 목록은 원시 값 대신 현재 언어의 이름으로 표시합니다.
- 도구·파일 제한 13개는 도구 반복, 첨부 및 다운로드, PDF 처리, 임시 파일 정리 네 묶음으로 나눠 표시합니다.
- 사이드바 머리글에 앱 이름과 아이콘 하나만 남겼습니다. PC에서는 접기, 모바일 서랍에서는 닫기 버튼이 됩니다.
- 채팅 기록의 제목 변경·삭제 버튼이 한 줄 안의 한 묶음으로 정리되어 더 이상 줄이 두 줄로 깨지지 않습니다. 터치 화면에서는 항상 보입니다.
- 접힌 사이드바의 아이콘은 좁은 레일 가운데에 정렬됩니다.

검증: `npm test`, `npx tsc --noEmit`, `npm run build`.

## 하네스 설정과 채팅 기록 (1.9.0)

관리자 설정의 **하네스 설정**에서 기존 도구·파일 제한과 다음 항목을 관리합니다.

- 컨텍스트 처리: 기본 **Rolling**은 오래된 대화 턴을 모델 입력에서 제외합니다. **Compacting**은 지정한 임계값(기본 80%, 10~95%)에 도달하면 이전 대화를 요약합니다. 요약 모델·추론 강도와 별도 큰 편집 창의 프롬프트를 설정할 수 있습니다.
- 압축 요약은 SQLite에 분기별로 별도 저장됩니다. 원문을 수정하면 이전 요약의 일치 여부를 검증해 다시 압축하며, 화면·내보내기·검색에는 원문이 남습니다. 도넛은 실제 모델 입력·출력 사용량을 표시하고, 서버 사용량이 없으면 다국어 텍스트 및 이미지 비용을 추정합니다. 컨텍스트 한도 정보가 없는 모델에는 자동 처리를 적용하지 않으므로 모델 설정에서 한도를 지정하세요. 최신 턴이나 압축할 한 턴이 너무 크면 명시적인 오류를 표시합니다.
- 채팅 제목 생성은 기본 비활성화입니다. 활성화하면 첫 응답 전 또는 첫 응답 후 중 선택한 시점에 생성합니다. 모델 기본값은 현재 채팅의 기반 모델(Alias도 기반 모델), 추론 기본값은 Off입니다. 지원하지 않는 추론 값은 전달하지 않습니다. 제목 생성 실패 시 채팅은 계속되며 기존 제목을 유지합니다.
- 각 채팅의 연필 버튼으로 제목을 변경합니다. 직접 변경한 제목은 자동 생성이나 오래된 응답 저장이 덮어쓰지 않습니다.
- 검색 버튼은 모든 분기의 원문과 제목을 검색하는 모달을 엽니다. 다른 분기 결과에는 분기 아이콘이 표시되고 선택하면 해당 분기로 이동합니다. 결과는 최신 대화순, 최대 100개입니다.
- PC 사이드바를 접으면 펼치기·새 채팅·검색·프로필 아이콘만 남습니다. 접힘 상태는 해당 브라우저에 저장됩니다.

하네스 모델 호출도 연결별 모델 상주 한도와 대기 정책을 사용합니다. 토큰 계산은 모델별 토크나이저 대신 추정값을 사용하므로 임계값과 실제 서버 사용량에는 차이가 있을 수 있습니다. 응답과 도구 정의를 위한 공간도 예약합니다.

검증: `npm test`, `npx tsc --noEmit`, `npm run build`, `node scripts/test-harness-integration.mjs` (빌드 후 실행, 임시 DB와 모의 모델 서버 사용).

## 서버별 모델 상주 한도와 대기 메시지 (1.8.3)

설정 → 연결에서 서버별 **최대 모델 상주 한도**와 **다른 세션 실행 중 대기 방식**을 선택합니다. 한도의 기본값 `0`은 제한 없음이며, 1~128은 LLM 상주 인스턴스 수 제한입니다. 한도를 설정하면 전역 On demand 설정이 꺼져 있어도 필요한 모델을 자동 로드합니다. 새 한도는 이후 시작하는 요청에 적용되며, 기존에 로드된 모델을 설정 저장만으로 즉시 내리지는 않습니다.

- **교체 후보가 모두 사용 중일 때만 대기**: 이미 상주한 모델은 동시 실행할 수 있습니다. 공간이 부족하면 사용 중이지 않은 모델 중 이 앱의 누적 사용 횟수가 가장 적은 모델을 내립니다. 동률이면 마지막 사용이 오래된 모델부터 교체합니다.
- **다른 세션이 실행 중이면 항상 대기**: 모델과 공간 여유에 관계없이 이 앱에서 실행 중인 해당 서버의 응답이 끝난 후 다음 요청을 실행합니다. 도구 실행과 사용자 선택 대기도 해당 응답에 포함합니다.
- 모든 사용자·대화의 사용 상태를 함께 관리하며, Alias는 기반 모델과 상주 공간 및 사용 횟수를 공유합니다. 사용 횟수는 SQLite에 저장되어 재시작 후에도 유지됩니다. 같은 서버 루트 URL을 사용하는 연결은 상주 관리와 가장 엄격한 설정을 공유합니다.
- 자동 로드·교체는 LM Studio native API와 기존 `/api/inference` 관리 API를 지원합니다. LM Studio를 OpenAI 호환 연결로 등록해도 native 관리 API를 자동 감지합니다. 관리 API가 없는 서버는 한도를 0으로 사용하세요. 서버가 외부 앱의 사용 상태를 제공하지 않으면 외부 세션의 실행 여부는 알 수 없으므로 자동 보호는 이 앱의 세션 기준입니다. 관리자의 수동 언로드는 기존과 같이 사용 중에도 가능합니다.

대기 문구는 응답 영역에 표시되고, 완료·중단·오류 때 사라집니다. 다른 세션 대기, 공간 확보(언로드), 모델 로드, 서버 응답 대기, 응답 준비의 다섯 단계를 구분합니다. 서버 응답이 5초 이상 없거나 연결이 거부되면 서버 응답 대기로 표시하며 중단할 수 있습니다. OpenAI 호환 스트림은 정확한 Prefill 이벤트를 제공하지 않으므로 응답 준비는 요청 시작부터 첫 출력까지의 준비 구간을 나타냅니다. 이미 전달됐을 수 있는 추론 요청은 중복 실행하지 않도록 자동 재전송하지 않습니다.

## 모델별 추론 설정 (1.8.2)

- 서버가 토글만 제공하면 **Fast / Thinking**, effort를 제공하면 **Fast / 지원되는 effort**를 기본 제공합니다. 끄기를 지원하지 않는 모델에는 Fast를 만들지 않으며, 추론 제어가 없는 모델은 Default와 커스텀 템플릿을 사용합니다.
- LM Studio의 `capabilities.reasoning.allowed_options`를 모델 이름보다 우선합니다. OpenAI 호환 연결도 같은 서버의 LM Studio 모델 메타데이터가 있으면 사용합니다.
- Alias의 추론 기능은 실제 연결된 기반 모델에서 상속합니다. 기반 모델 변경과 재감지 시 지원 프리셋을 다시 구성하고 커스텀 템플릿과 순서를 유지합니다.
- 커스텀 시스템 프롬프트의 대체/앞에 추가/뒤에 추가를 계속 지원합니다. 기반 모델에서 지원하지 않는 과거 effort 값은 요청에서 제외합니다.
- **기존 설치를 업데이트한 경우 설정 → 연결에서 모델 감지를 실행하고 저장**하여 저장된 추론 메타데이터를 갱신하세요. Qwen3.8 파생 모델도 서버가 `off/on`만 광고하면 Fast / Thinking으로 표시됩니다.

## 간편 호스팅

Node.js 22 이상과 Python 3가 설치되어 있으면 운영체제별 스크립트가 Node 의존성 및 DDGS용 격리 Python 환경 설치, 프로덕션 빌드, standalone 정적 파일 준비와 서버 시작을 처리합니다. 최초 실행 시 앱 기본값을 `data/neural-chat.sqlite3`에 저장하며 이후 사용자, 세션, API 연결, 모델, 화면 환경설정은 모두 SQLite에서만 읽고 씁니다.

Windows:

```bat
host-windows.bat
```

Linux 또는 LXC:

```bash
chmod +x host-linux.sh
./host-linux.sh
```

소스나 패키지를 업데이트한 뒤에는 `host-windows.bat --rebuild` 또는 `./host-linux.sh --rebuild`로 다시 빌드합니다. `app-config.json`은 애플리케이션 데이터가 아닌 서버 프로세스 자체의 설정만 담당합니다.

```json
{
  "server": {
    "host": "0.0.0.0",
    "port": 3000,
    "accessMode": "lan-and-tailscale"
  }
}
```

`PORT`와 `NEURAL_CHAT_HOST` 환경 변수는 파일 값보다 우선합니다. `NEURAL_CHAT_DATA_DIR` 또는 `NEURAL_CHAT_DB_PATH`로 저장 위치를, `NEURAL_CHAT_SERVER_CONFIG`로 서버 설정 파일 경로를 따로 지정할 수 있습니다.

`server.accessMode`는 Windows MSI 서비스의 원격 접속 범위를 정합니다. 허용값은 `lan`, `tailscale`, `lan-and-tailscale`입니다. 로컬 루프백 접속은 항상 허용되며, 그 외 인터넷 주소는 거부됩니다.

실제로 서버를 시작하지 않고 설치와 빌드 상태만 준비·확인하려면 `--check`를 사용합니다.

```bash
./host-linux.sh --check
```

## Windows MSI 설치

`installer/output/NeuralNetUI-2.1.4.1-x64.msi`는 Node.js, 앱 런타임, 헤드리스 Chromium, Windows 서비스와 트레이 앱을 함께 포함합니다. 설치 화면의 **Hosting access** 단계에서 LAN만, Tailscale만, 또는 둘 다를 선택하고 수신 포트를 지정할 수 있습니다. 설치가 끝나면 `NeuralNetUI Service` Windows 서비스가 자동 시작 유형으로 등록되고 현재 사용자에게 Web UI와 트레이 아이콘이 열립니다. 이후 Windows 부팅 때는 서비스가 먼저 시작되며, 사용자가 로그인하면 Web UI와 트레이 아이콘이 자동으로 열립니다.

트레이 아이콘을 두 번 누르면 Web UI를 다시 열 수 있습니다. 우클릭 메뉴에는 **설정 파일 수정**, **재시작**, **종료하기**가 있으며, 종료는 서비스와 트레이 앱을 함께 중지합니다. 시작 메뉴의 **NeuralNetUI**를 누르면 중지된 서비스를 다시 시작하고 Web UI를 호스팅하며 트레이 아이콘도 복원합니다. 서비스 제어와 보호된 설정 파일 편집에는 Windows 관리자 권한 확인이 표시될 수 있습니다.

설치된 호스팅 설정은 `%ProgramData%\Neural Chat\app-config.json`에 있습니다. 파일에서 `server.port` 또는 `server.accessMode`를 바꾼 뒤 관리자 권한으로 `Restart-Service NeuralChat`을 실행하면 서비스와 Windows 방화벽 규칙이 새 설정으로 동기화됩니다. 앱 데이터와 로그는 `%ProgramData%\Neural Chat\data`에 보존됩니다.

무인 설치에서도 같은 공개 MSI 속성을 사용할 수 있습니다.

```powershell
msiexec /i NeuralNetUI-2.1.4.1-x64.msi /qn ACCESS_MODE=tailscale APP_PORT=65500
```

MSI를 다시 빌드하려면 Node.js, .NET 8 SDK가 있는 Windows x64 개발 환경에서 다음을 실행합니다. WiX 5 도구는 처음 빌드할 때 `installer/.tools`에 로컬 설치됩니다.

```powershell
.\installer\build-msi.ps1
```

Docker Desktop(Windows) 또는 Docker Engine과 Docker Compose v2(Linux)가 설치되어 있으면 운영체제별 스크립트 하나로 이미지를 빌드하고 컨테이너를 시작할 수 있습니다.

Windows:

```bat
deploy-docker-windows.bat
```

Linux:

```bash
chmod +x deploy-docker-linux.sh
./deploy-docker-linux.sh
```

기본 접속 주소는 `http://localhost:3000`이며 SQLite DB와 업로드 파일은 프로젝트의 `data` 디렉터리에 계속 보존됩니다. 외부 포트를 바꾸려면 실행 전에 `NEURAL_CHAT_PORT`를 지정합니다.

set NEURAL_CHAT_PORT=65500
deploy-docker-windows.bat

```bash
NEURAL_CHAT_PORT=65500 ./deploy-docker-linux.sh
```

호스트 PC에서 실행 중인 OpenAI 호환 API 서버에 연결할 때는 앱 설정의 Base URL에 `http://host.docker.internal:8888/v1`처럼 `host.docker.internal`을 사용합니다. Windows와 Linux 모두 Compose에서 이 호스트 이름을 사용할 수 있도록 설정되어 있습니다.

컨테이너 로그 확인과 종료는 다음 명령으로 할 수 있습니다.

```bash
docker compose logs -f neural-chat
docker compose down
```

## LXC 배포

Node.js 22 이상이 설치된 LXC에서 다음 순서로 수동 빌드할 수도 있습니다. Docker는 필요하지 않습니다.

```bash
npm ci
npm run build
mkdir -p /opt/neural-chat
cp -a .next/standalone/. /opt/neural-chat/
cp -a .next/static /opt/neural-chat/.next/static
mkdir -p /opt/neural-chat/scripts
cp scripts/start-server.mjs /opt/neural-chat/scripts/
cp scripts/ddgs-search.py /opt/neural-chat/scripts/
cp scripts/process-pdf.py /opt/neural-chat/scripts/
cp requirements.txt /opt/neural-chat/
cp app-config.json /opt/neural-chat/
```

정적 자산 폴더가 추가되면 `public`도 `/opt/neural-chat/public`으로 복사합니다. `deploy/neural-chat.service.example`을 `/etc/systemd/system/neural-chat.service`로 복사하고 사용자·경로를 환경에 맞게 조정한 뒤 실행합니다.

```bash
systemctl daemon-reload
systemctl enable --now neural-chat
```

앱 설정과 대화 데이터는 기본적으로 실행 디렉터리의 `data/neural-chat.sqlite3`에 저장됩니다. 운영 환경에서는 예시 서비스처럼 `NEURAL_CHAT_DATA_DIR=/var/lib/neural-chat`을 반드시 지정하고 해당 디렉터리를 서비스 사용자만 읽고 쓸 수 있게 두는 것을 권장합니다. DB 파일만 별도 위치에 둘 경우 `NEURAL_CHAT_DB_PATH`를 사용할 수 있습니다. 저장된 API 키는 브라우저 응답에 다시 포함되지 않습니다.

SQLite는 WAL 모드, 외래키 검사, 5초 busy timeout을 사용하며 대화의 모든 브랜치와 메시지는 한 트랜잭션으로 저장됩니다. 사용자 메시지 편집, 모델 응답 편집, 응답 재생성은 모두 기존 경로를 보존한 새 브랜치를 생성합니다. 수정본이 있는 각 메시지 아래의 `< m / n >` 탐색기로 해당 메시지의 이전·다음 수정본과 연결된 채팅 기록을 즉시 전환할 수 있습니다. 내보내기는 선택 브랜치의 Markdown 또는 모든 브랜치가 포함된 JSON을 지원합니다.

이미지와 PDF를 메시지에 함께 첨부할 수 있습니다. 이미지 메타데이터와 메시지 연결은 SQLite에 저장하고, DB 비대화를 막기 위해 원본과 브라우저에서 생성한 경량 썸네일은 `data/uploads`에 분리 저장합니다. PDF는 원본과 제한된 텍스트 추출 캐시만 보관하며, 텍스트가 없는 스캔 PDF는 모델 요청 시 제한된 페이지를 임시 이미지로 렌더링한 뒤 즉시 삭제합니다. 대화에서 참조되지 않은 업로드는 설정된 보관 시간이 지난 뒤 다음 업로드 요청에서 정리됩니다.

페이지 방문 도구는 HTML뿐 아니라 JSON, XML, CSV 등 텍스트 응답을 읽습니다. PDF URL은 임시 파일로 처리하고 즉시 삭제하며, 안전한 래스터 이미지는 비전 입력으로 전달합니다. 압축 파일과 실행 파일을 포함한 기타 바이너리는 열지 않습니다. 설정의 **Tools** 탭에서 최대 도구 호출 라운드, 메시지당 첨부 수, 텍스트·이미지·PDF 용량, PDF 페이지·추출 글자·비전 페이지 수, 처리 제한 시간과 미첨부 업로드 보관 시간을 변경할 수 있습니다. 관리자가 입력한 값은 서버 안전 범위 안에서 검증됩니다.

기존 `data/config.json`, `data/conversations/*.json`, `data/uploads/*.json`은 최초 실행 때 한 번 자동으로 SQLite에 이전됩니다. 이전이 끝난 원본 파일은 안전을 위해 삭제하지 않으며 이후에는 SQLite 데이터가 기준이 됩니다. 구버전 `app-config.json`에 앱 설정을 보관했다면 업데이트 전에 해당 파일을 `data/config.json`으로 복사하면 같은 이관 경로를 사용할 수 있습니다.

긴 대화는 최근 60개 메시지만 먼저 렌더링하고 이전 메시지를 60개 단위로 추가 표시합니다. 사이드바 기록은 전체 대화 대신 SQLite 요약 쿼리만 읽습니다.

## 운영 및 백업

관리자는 모델 선택기에서 **생성 중에도 모델을 언로드**할 수 있습니다. 서버 부하를 줄이는 동작을 우선하며, 해당 모델을 사용하는 생성은 서버 응답에 따라 중단되거나 오류로 종료될 수 있습니다. 설정의 **저장된 API 키 삭제**는 저장 시 기존 키와 환경 변수 키 대체 사용을 함께 끕니다. 새 키를 입력하면 키 사용이 다시 활성화됩니다.

선택형 질문 대기 중에도 생성 중단 버튼을 사용할 수 있습니다. 서버 재시작 등으로 질문 작업이 사라진 경우 대화를 다시 열면 일반 입력이 복구됩니다. 대화 삭제는 진행 중 작업도 폐기하며, 완료 작업 캐시는 60초 또는 최대 64개까지만 유지합니다.

회귀 검증은 `npm test`, `npx tsc --noEmit`, `npm run build` 순서로 실행합니다. 빌드 후 `node scripts/test-audit-integration.mjs`를 실행하면 임시 DB와 로컬 모의 LM Studio 서버로 설정 권한, 모델 라우팅, 스트림 실패, 대화 삭제, 질문 복구, 작업 캐시 제한을 검사합니다. 실제 연결 설정과 모델에는 접근하지 않습니다.

SQLite와 로컬 업로드 파일을 사용하므로 한 데이터 디렉터리를 여러 앱 인스턴스가 동시에 공유하지 마세요. 다중 인스턴스가 필요하면 PostgreSQL과 객체 스토리지로 이전해야 합니다. 실행 중인 DB는 WAL 파일만 단순 복사하지 말고 SQLite의 online backup 기능으로 백업한 뒤 `uploads` 디렉터리도 함께 보관합니다.

```bash
sqlite3 /var/lib/neural-chat/neural-chat.sqlite3 ".backup '/backup/neural-chat.sqlite3'"
cp -a /var/lib/neural-chat/uploads /backup/uploads
```

모델 응답은 GitHub Flavored Markdown과 KaTeX 기반 LaTeX로 렌더링되며 목록, 링크, 표, 인라인/블록 수식, 인라인 코드와 코드 블록을 지원합니다. 설정의 **모양** 패널에서 모델 identifier 표시와 단일·이중 물결표 취소선 렌더링을 사용자별로 켜거나 끌 수 있습니다. 사용자 메시지는 입력한 일반 텍스트 그대로 표시됩니다. 모바일 입력창의 Enter는 줄바꿈이며, 데스크톱에서는 Enter로 전송하고 Shift+Enter로 줄바꿈합니다. 완료된 모델 응답은 응답 아래의 편집 버튼으로 현재 브랜치 안에서 수정할 수 있습니다.

## 사용자와 권한

- 사용자 테이블이 비어 있는 최초 접속에서는 최고 관리자 계정을 생성합니다. 기존 버전에서 이전된 대화와 업로드는 이 계정에 귀속됩니다.
- 최고 관리자와 관리자는 설정에서 일반 사용자 또는 관리자 계정을 추가하고, 다른 사용자의 표시 이름을 변경하거나 계정을 삭제할 수 있습니다. 최고 관리자 계정과 현재 로그인한 본인 계정은 삭제할 수 없습니다.
- 대화와 이미지 업로드는 사용자별로 분리되며 다른 사용자의 API 접근도 거부됩니다.
- 커스텀 모델은 만든 사용자에게만 보입니다. 제작자가 **커스텀 모델 공개**를 켜면 다른 사용자도 채팅에서 사용할 수 있지만 수정할 수는 없습니다.
- 일반 사용자의 설정 화면은 자신이 만든 커스텀 모델, 자신이 만든 커스텀 Reasoning 프리셋, 계정 비밀번호 변경만 제공합니다.

## 인터넷 도구

입력창의 `+` 메뉴에서 **인터넷 검색**, **페이지 방문**, **브라우저**를 각각 켤 수 있습니다. 활성화된 도구만 OpenAI 호환 `tools` 정의로 모델에 전달되고, 모델이 호출하면 서버가 결과를 실행해 같은 요청 흐름 안에서 모델에 돌려줍니다. 검색은 Python `ddgs` 패키지를 사용합니다. 페이지 방문과 브라우저는 공개 HTTP(S) 주소만 허용하며 localhost와 사설 IP 대역을 차단합니다.

**브라우저** 도구는 실제 Chromium에서 JavaScript를 실행합니다. 모델은 `open`, `inspect`, `click`, `type`, `select`, `press`, `scroll`, `wait`, `screenshot`, `close` 작업을 연속 호출할 수 있고, DOM 스냅샷에 포함된 `e1`, `e2` 같은 요소 참조로 페이지를 조작합니다. `open` 또는 `screenshot`에 `wait_seconds`를 지정하면 최대 30초를 기다린 뒤 화면을 캡처하며, 캡처 이미지는 모델의 비전 입력으로도 전달됩니다. 전체 페이지 캡처는 메모리 남용을 막기 위해 높이 8,000px까지로 제한됩니다. 세션은 사용자와 응답별로 격리되고 응답 종료 시 자동으로 닫히며, 서브리소스 요청에도 공개 주소 검사를 적용합니다.

Docker 이미지와 Windows MSI는 Chromium을 포함합니다. 소스에서 직접 실행할 때 Chrome 또는 Edge가 설치되어 있지 않다면 `npm run browser:install`을 한 번 실행하세요. 별도 Chromium 실행 파일은 `NEURAL_CHAT_BROWSER_EXECUTABLE` 환경 변수로 지정할 수 있습니다.

한 응답에서 발생한 도구 호출은 렌치 아이콘이 있는 하나의 **도구 사용 중/도구 사용함** 폴딩에 모입니다. 각 호출은 **인터넷 검색 도구 사용 중**, **페이지 방문 도구 사용함**처럼 이름과 상태를 표시하는 하위 폴딩이며, 펼치면 도구 호출 인자와 결과를 확인할 수 있습니다. 진행 중인 호출은 자동으로 펼쳐지고 완료된 호출은 접힌 상태로 정리됩니다.

다중 선택 도구의 질문은 기술적인 도구 폴딩 대신 입력창 위의 전용 카드에 한 번에 하나씩 표시됩니다. 모델은 질문별로 단일 선택, 복수 선택, 우선순위 정렬 방식을 지정할 수 있으며, 답변 후에는 다음 질문으로 슬라이드 전환됩니다. 제출한 질문·답변 쌍은 사용자 메시지 형태로 대화에 표시되고 모델 응답이 이어집니다.

사용자 메시지를 삭제하면 같은 브랜치에서 바로 연결된 모델 응답도 함께 삭제됩니다.

직접 실행하는 경우 아래 의존성도 설치할 수 있습니다. `host-windows.bat`와 `host-linux.sh`, Docker 이미지는 이를 자동 처리합니다.

```bash
python -m pip install -r requirements.txt
```

## 모델 서버 연결

- `설정 > 연결`에서 OpenAI API 또는 LM Studio 드라이버를 선택해 여러 서버를 추가할 수 있습니다.
- LM Studio는 기본 주소 `http://localhost:1234`와 네이티브 `/api/v1/models`, `/api/v1/models/load`, `/api/v1/models/unload`를 사용합니다. 채팅은 도구 호출과 전체 대화 이력을 보존하기 위해 LM Studio의 `/v1/chat/completions` 호환 스트림을 사용합니다.
- 연결 카드를 드래그하거나 위/아래 버튼으로 정렬할 수 있습니다. 같은 모델 identifier가 여러 서버에 있으면 가장 위 연결이 선택됩니다.
- 감지된 모델, 표시 여부, 설명, 시스템 프롬프트, 컨텍스트 길이와 Reasoning 프리셋은 연결별로 저장되므로 다른 서버를 사용한 뒤 돌아와도 복원됩니다.

## Reasoning 동작

- **Built-in** 프리셋은 선택한 값을 OpenAI 호환 요청의 `reasoning_effort`로 전달합니다.
- **Custom template**은 선택한 내장 effort를 전달한 뒤, 템플릿 내용을 모델/alias 시스템 프롬프트 뒤에 추가합니다.
- Qwen3.8의 화면상 **Extra High**는 실제 서버가 허용하는 API 값인 `xhigh`로 전송됩니다.
- 입력창의 Reasoning 메뉴에서 이전 assistant 응답의 `reasoning_content`를 다음 요청에 포함할지 선택할 수 있습니다.
- Reasoning 생성 중에는 최근 내용이 약 5줄 높이로 스트리밍되고, 완료 후에는 실제 측정한 소요 시간을 `Thought for …` 또는 `… 동안 생각함`으로 표시합니다.
- OpenAI 모델 감지는 `/models` 메타데이터와 잘 알려진 reasoning 모델 이름을 사용합니다. LM Studio는 `/api/v1/models`가 제공하는 `capabilities.reasoning.allowed_options`를 우선합니다. 설정에서 언제든 수동으로 덮어쓸 수 있습니다.
- `/models`가 반환한 항목은 Models 관리 목록에 모두 보존됩니다. 모델별 **메인 인터페이스에 표시** 토글을 끄면 모델 선택기와 Reasoning 설정 목록에서만 숨겨집니다.
- 숨긴 서빙 모델은 커스텀 alias의 기반 모델 선택 목록에서도 제외됩니다.
- 커스텀 Reasoning 템플릿의 시스템 프롬프트는 모델 프롬프트를 `Replace`, `Prepend`, `Append`하는 세 가지 방식으로 조합할 수 있습니다.
- 커스텀 모델은 별도 모델을 복제하지 않는 alias입니다. 표시 이름과 ID, 시스템 프롬프트만 독립적으로 가지며 요청은 기반 모델의 ID로 전송됩니다.
- 일반 설정의 **On demand**를 켜면 각 추론 요청 전에 드라이버에 맞는 load API를 호출합니다. OpenAI 드라이버의 `repo:variant` 형식 ID는 `model_path`와 `gguf_variant`로 나누고, LM Studio에는 `model`과 선택적 `context_length`를 전송합니다.
- 관리자 계정은 모델 선택 메뉴의 **로드된 모델 언로드** 버튼으로 서버의 현재 추론 모델을 메모리에서 내릴 수 있습니다. 서버 부하를 줄일 수 있도록 모델 생성 중에도 버튼을 사용할 수 있습니다.
- 모델 및 Reasoning 선택기 하단의 **기본으로 사용**으로 다음 로그인/접속의 초기 모델과 추론 강도를 계정별로 저장할 수 있습니다. 기존 대화에서 **새 채팅**을 누르면 현재 선택은 유지됩니다.
- 일반 설정에서 모델, alias, 가시성, Reasoning 프리셋과 기본 선택을 2-space JSON으로 내보내거나 다시 가져올 수 있습니다. 가져온 설정은 검증 후 즉시 저장됩니다.

응답 스트리밍 중에는 사용자가 대화 하단을 보고 있는 동안만 새 내용을 자동으로 따라갑니다. 사용자가 위로 스크롤하면 자동 스크롤이 멈추고, 다시 하단으로 이동하면 자동 추적이 재개됩니다.

## 컨텍스트 압축과 출력 재개 (2.1.3)

하네스 → 컨텍스트 처리 → 압축에서 임계값, 압축 프롬프트, 재개 프롬프트와 최대 재개 횟수를 설정합니다. 전송 전에는 이전 대화를 먼저 압축하고, 출력 중에는 답변·추론·도구 호출 인자를 포함한 사용량을 매 스트림 이벤트에서 검사합니다. 서버 토큰 사용량이 없을 때는 추정값을 사용합니다.

임계값에 도달하면 현재 추론 요청을 취소하고 진행 내용을 압축한 뒤 원래 사용자 요청과 함께 재개합니다. 재개 템플릿의 `%COMPRESSED%`는 압축 요약, `%USER_PROMPT%`는 원래 사용자 메시지입니다. 사용자 첨부 이미지는 재개 요청에도 유지됩니다. 끊긴 도구 호출은 실행하지 않습니다.

최대 재개 횟수는 응답 하나당 기본 3회이며 0~100회로 설정합니다. 전송 전 압축은 제외됩니다. 한도 초과 시 출력은 보존하고 임계값 또는 모델 컨텍스트 길이를 늘리라는 오류를 표시합니다. 압축 후에도 입력이 임계값 이상이면 무한 재시도 없이 오류를 표시합니다. 원문 대화는 보존됩니다.

회귀 검증: `npm test`, `npx tsc --noEmit`, `npm run build`, `node scripts/test-compaction-integration.mjs`.
