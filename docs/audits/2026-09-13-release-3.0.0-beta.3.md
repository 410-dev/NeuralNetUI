# 3.0.0-beta.3 validation

## Permission matrix

- Partial trust now opens a dedicated 27-row permission matrix instead of five broad risk switches.
- File search, inspection, reading, copy, overwrite-copy, write, overwrite-write, rename, move, overwrite-move, delete, and recursive delete are independent choices.
- Temporary upload, process start/list/kill, screenshot capture, and PowerShell/Bash risk levels 1 through 5 are separately approval-gated.
- Every row is exclusive between automatic approval and always ask. Unknown actions remain approval-gated, and beta-2 risk settings migrate only to their equivalent detailed operations.

## Owned file storage

- Migration 11 adds a per-user storage quota, retained upload marker, and administrator audit log. New-user quota defaults to 512MB and is configurable from 1MB to 10TB.
- Upload quota reservation and quota reduction both run in SQLite transactions, preventing a concurrent upload from committing across a quota change.
- Chat attachments and browser/host screenshots are owned by one user and served through authenticated URLs. Retained screenshots survive orphan cleanup; files referenced by saved messages cannot be deleted from Storage manager.
- Native LM Studio inference prepares images from their local file path. OpenAI-compatible HTTP materializes base64 only immediately before the provider request, rather than persisting it in chat/tool state.
- The sidebar Storage manager reports used/allocated capacity, previews and downloads owned media, and offers confirmed deletion for unreferenced files.

## User administration and audit export

- The user overview reports each account's used/allocated storage plus aggregate used and aggregate allocated capacity. It also edits the default quota for subsequently created accounts.
- Role, display name, and MB/GB quota controls moved into a dedicated user-management modal. A quota cannot be reduced below current usage; Superadmin role protections remain in force.
- Administrators can inspect and export complete conversations including every branch, individually or in a combined ZIP. Media can be previewed/downloaded individually or packaged into a ZIP.
- JSON conversation entries use DEFLATE; already-compressed media is streamed into the ZIP without buffering entire files. ZIP32 file-count, per-file, and archive-size limits fail explicitly instead of producing a corrupt archive.
- User inspection and export operations are written to `admin_audit_log`. Ordinary users receive HTTP 403 from the audit endpoint.
