# 3.0.0-beta.15 validation

Date: 2026-09-16 (Asia/Seoul)

## Scope

Beta 15 adds versioned, high-compression 7z backup images and merge/replace restore for every account. Administrators receive separate global-settings, account-credential, and paginated per-user image management. The release also adds administrator-defined plans, model access and weights, multiple first-use-anchored token windows, plan storage, per-user assignment, reset credits, and the sidebar usage donut.

## Safety and data behavior

- Personal images contain every owned conversation branch, message, attachment relation, upload record and media file plus personal preferences; password hashes are excluded.
- Account-credential images contain scrypt password hashes, roles, preferences, quotas, plan assignments, plans, limits and reset-credit grants. Session tokens are never exported.
- The image format has its own integer version (`1`). A future image is rejected. Older images pass through one adapter at a time before restore.
- Restore lists the archive before extraction and rejects absolute/traversal/alternate-stream paths, excessive entry counts, unpacked data above free-disk or 10 TB limits, and post-extraction symbolic links.
- Restore whitelists every database column, validates owned identifiers, original media presence and byte sizes, and verifies active/trash quotas.
- Merge replaces records with matching identifiers and retains unrelated data. Replace removes the selected scope. Media is staged beside its destination; overwritten files are retained until the SQLite transaction commits and restored on failure.
- Active chat jobs are cancelled before personal restore. Account restore must retain the acting administrator, updates retained users without SQLite `REPLACE` cascades, and omits all sessions.
- Token usage includes regular model turns and harness title/compaction calls. Output is capped by the nearest eligible window. A per-account database admission row serializes concurrent responses so several requests cannot all pass the same remaining allowance.

## Follow-up of 2026-09-17: plan directories and backup repair

### Findings

- Docker: every backup and restore failed with `spawn /app/node_modules/7zip-bin/linux/x64/7za EACCES`. The npm `7zip-bin` 5.2.0 tarball does not keep the executable bit on its Linux binary, so the traced copy in the image was mode 644. The previous validation only ran on Windows, where the bit does not exist.
- Account-credential Replace failed with `FOREIGN KEY constraint failed` when an account missing from the image owned a chat that referenced its own upload: deleting the user cascaded to uploads while `message_attachments` still held a RESTRICT reference. Reproduced on the pre-fix build by the new backup integration.
- Global-settings Merge behaved exactly like Replace.
- Account Merge surfaced raw SQLite UNIQUE errors for username or plan-name collisions and left stale token limits beside imaged ones.
- A single upload whose original file was missing aborted a whole personal or per-user image.
- Resolving 7-Zip from `process.cwd()` made Turbopack trace the entire repository into the standalone server. The first rebuild in this follow-up grew the MSI by about 15 MB before this was fixed.

### Changes

- The Dockerfile marks the traced 7-Zip binary executable. At run time `bundled7z()` checks `X_OK`, repairs the mode, or runs a private temporary copy when the install directory is read-only. Verified in the container by resetting the binary to 644 before a backup.
- Account restore validates username, plan-name, plan-limit and credit-author references before the transaction. Replace removes departing accounts' conversations before the accounts, clears their private aliases and presets through the shared `removeOwnedConfigEntries`, drops reset credits missing from the image, and deletes their stored files after commit.
- Global Merge overlays the image while keeping connections and models that the image does not name.
- Personal and per-user images omit uploads without an original, together with their attachment rows, and list them in `manifest.skippedUploads`; `.tmp`, `.restore` and `.backup` files are never imaged.
- Migrations 16 and 18 seed the first plan's storage and trash capacity from the workspace defaults when an older installation upgrades.
- Only `node_modules/7zip-bin/{index.js,package.json}` and the build platform's binary are traced for `/api/backup`.
- Plans gained a trash quota; plan assignment, reset-credit recipients and per-user images moved to searchable, sortable, paginated directory dialogs with persistent multi-selection; user reset credits accept several recipients in one transaction.
