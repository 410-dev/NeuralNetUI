# 3.0.0-beta.9 validation

## Browser rendering and Google sign-in compatibility

- Windows shared browsing now prefers an installed stable Google Chrome, then stable Microsoft Edge, before the bundled Chrome for Testing fallback. Explicit administrator configuration remains highest priority.
- The headed off-screen browser disables occlusion, background timer and renderer throttling. Public DNS decisions use a bounded 30-second cache instead of resolving the same host for every subresource, and the live frame poll interval changed from 700ms to 400ms.
- Playwright's `--enable-automation` default is omitted, the AutomationControlled Blink feature is disabled, and `navigator.webdriver` is hidden in new isolated contexts.
- The browser unit regression verifies executable priority and launch flags. The live Google smoke opened `https://accounts.google.com/` in the selected installed stable browser without an immediate unsafe-browser rejection. No account credentials were used, so an authenticated account-completion flow was not performed.
- Source and packaged-standalone browser-view integration passed headed multi-tab state, tab labels, authenticated user controls, model-to-human handoff, response persistence, and explicit close.

## Tool approval and large-image handling

- Accepting any waiting tool input now changes its persisted/live event from `waiting` to `calling` before execution resumes. The host approval composer therefore unmounts immediately and the existing tool activity UI displays active work during a long operation.
- Stored and downloaded images remain byte-for-byte original. Model context resolves a separate, atomically generated and cached JPEG derivative bounded to 1,600px on either side, preventing the OpenAI-compatible path from reading and base64-encoding the large original.
- The storage regression used a 2,800x1,800 PNG, verified the model path was a separate JPEG no larger than 1,600px, and verified the original bytes and dimensions remained unchanged.

## Personal storage

- The personal storage manager requests exactly five files per page.
- A trash icon performs single-file soft deletion. A 500ms press (including mobile context-menu interception) enters check-marked multi-select mode, where up to 100 files can be deleted atomically.
- Files referenced by saved chats remain visibly protected and cannot be included in deletion. The server validates ownership, existence and reference protection for the complete batch before updating any row.
- Source and packaged-standalone UI integration created seven files, verified 5/2 pagination, exercised single deletion and long-press two-file deletion, confirmed five records in the audit trash view, and checked the 390x844 layout for horizontal overflow.
