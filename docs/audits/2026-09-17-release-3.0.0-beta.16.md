# 3.0.0-beta.16 — encrypted portable backups

## Changes

- Require and verify the data owner's username/password for personal or per-user export, and the exporting administrator's credentials for global/account export.
- Stream the high-compression 7z image through AES-256-GCM. The versioned envelope authenticates its header and ciphertext; scrypt derives a 256-bit key using a random 16-byte salt, N=32768, r=8, p=1. GCM uses a fresh 12-byte nonce and 16-byte tag. Credentials are supplied in a request header, never a URL or subprocess argument. No password or instance secret is stored in the envelope.
- Restore verifies the original credentials and integrity before archive extraction or database mutation. Changing the login password does not re-encrypt older backups. Legacy plaintext archives require re-export from their source installation.
- Personal and per-user scopes interoperate. Cross-owner imports deterministically remap conversation, branch, message and upload IDs plus attachment URLs and filenames. Repeated imports are idempotent.
- Account restore requires a superadmin. Matching usernames map to destination IDs; the executing destination administrator is retained so a foreign image cannot remove their access. Destination quotas continue to apply to personal restoration.
- Serialize backup/restore requests; enforce the upload limit on actual stream bytes; restrict archive paths and reject links before extraction; validate personal graph membership.
- Fix file rollback to remove newly installed originals on a failed transaction, cover partial staging failures, and avoid treating post-commit housekeeping failures as transaction failures.
- Preserve the existing bilingual dialog, form and button design; expose progress and credential failures.
