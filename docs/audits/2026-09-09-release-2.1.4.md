# 2.1.4 validation

## Scope

Fixes the 2.1.3 compaction triggers and replaces the fixed assistant layout with an ordered transcript. Schema migration 10 adds `messages.steps`; existing messages have none and keep their previous layout. Streaming protocol, drivers, residency and tool execution are unchanged.

## Automated

- Unit suite: 111 passed. New `lib/transcript.test.ts` covers the legacy reconstruction, preservation of recorded order including text after a tool round, dropping of empty stages, and per-round tool resolution with unknown ids skipped. `lib/harness.test.ts` gained coverage for the decision never using the smaller of estimate and measurement, including the 89%-of-window case that used to slip past an 80% threshold.
- Type checking: `npx tsc --noEmit` passed. Production: `npm run build` passed.

## Interactive

Driven against a throwaway data directory and a mock model that reports honest `prompt_tokens` and, when resumed, emits only what is left.

Four compaction paths, with a 4,000-token window and a 60% threshold:

| case | result |
| --- | --- |
| History the interface reads as ~89% full | one compaction **before** the request, one chat call, completed, peak context 5%, steps `compaction → reasoning → content` |
| Threshold crossed while streaming | output stopped at 62% (never past 100%), one compaction, one resumed request, completed, steps `reasoning → content → compaction → reasoning → content` |
| Resume limit set to zero | stops at the first crossing with the localized "threshold too low or context too short" warning |
| Comfortable window (90% threshold) | nothing compacted |

Both defects the report described are gone: the send-time check now fires, and the mid-response check stops the output instead of running past the window.

Transcript rendering, measured from the DOM:

- A seeded message with stages `reasoning, content, tools, content, tools, compaction, content` renders in exactly that order, ending with the footer. A deliberately invalid tool id in one round was skipped rather than rendering a placeholder.
- The compaction fold shows two labelled panes, "압축 모델의 사고" and "맥락으로 유지되는 요약".
- A live generation with a tool round produced `reasoning → content → tools → reasoning(streaming) → content`, so the second turn's reasoning appears after the tool round rather than merged into the first.
- Round-trip integrity: the concatenated content stages equal `message.content`, and the rendered text equals the stages, so copying and export are unaffected.
- A message stored without stages renders `reasoning → tools → content`.
- The resume prompt dialog carries the `%COMPRESSED%` / `%USER_PROMPT%` explanation, and the note no longer sits loose under the buttons.

## Defects found and fixed during this work

- The first attempt passed the pre-compaction projection to the streaming turn and left the stale measurement in place, so a compacted request reported ~95% context and re-triggered compaction until the resume limit. The projection is recomputed after compacting and the measurement is discarded.
- Compaction was reported twice while running, once as a wait line and once as a stage. The stage now opens the moment the phase begins and the wait line stays quiet for it.

## Not verified

- Every scenario used a mock model. Real tokenizer behaviour, real summary quality, and whether a given model actually continues rather than restarting on resume were not measured.
- The mid-response paths depend on the model shortening its output when resumed. A model that regenerates a full-length answer each time will exhaust the resume limit; that is the safety valve, not a fix, and case C shows the warning it produces.
- No touch-device or non-Chromium pass.
- The MSI was packaged without installing it or restarting the user's service.
