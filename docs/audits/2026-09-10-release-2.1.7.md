# 2.1.7 validation

## Changes

Settings gain a workspace-wide reach and an account-level limit.

- `AppConfig.loginAppearance` is a new workspace-wide accent for the sign-in screen, written only by administrators. `/api/auth/status` serves the resolved hex unauthenticated so the sign-in screen can paint itself before any account exists. Signed-in sessions keep using the account's own accent.
- `PUT /api/config/defaults` (administrators only) records one default model or one reasoning level as the workspace default and stamps that single key onto every account, leaving each person's other preferences untouched. The model and reasoning pickers show it as "전체 적용" beside the existing personal "기본으로 사용".
- Standard accounts may still pin a served model or reasoning level as their own default, but no longer edit served models' reasoning templates. `writeConfigForUser` now carries served connections over untouched for non-administrators, so the restriction holds at the server, not only in the panel.

No database migration; user preference rows gain no new keys beyond the existing default model/reasoning ids.
