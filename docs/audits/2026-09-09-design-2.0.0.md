# 2.0.0 validation

## Scope

Presentation and one new preference group. Harness behaviour, chat streaming protocol, conversation storage, connection drivers and residency logic are unchanged. Migration count is unchanged; the new appearance preferences live in the existing per-user preference JSON and default to the previous behaviour, so existing installations look different but behave identically until a user changes a setting.

## Automated

- Unit suite: 86 passed, including a new `lib/appearance.test.ts` covering hex normalization, palette resolution, accent variable derivation, chunked reveal stepping and preference clamping.
- Type checking: `npx tsc --noEmit` passed. Production: `npm run build` passed. `git diff --check` passed.
- A test caught a real defect before it shipped: boosting saturation to derive the bright accent tinted achromatic colours, so the Graphite palette and any grey custom colour picked up a red cast. Saturation is now only raised for colours that already have some.

## Interactive

The application was launched for real against a throwaway data directory and a mock OpenAI-compatible model server, seeded through the API the same way `scripts/test-harness-integration.mjs` does, and driven in a browser. Verified there:

- Composer: single pill row at rest (`border-radius: 999px`); a long draft switches it to `expanded` with `34px` corners, the text on its own first row and the controls below; clearing the draft returns it to the pill. No oscillation between the two states.
- Dropdowns: zero native `select` elements remain in the app. The custom menu opens with `popover-in`, closes with `popover-out`, flips to `popover-in-up` when anchored to the bottom, and lists options with the model picker's checkmark treatment.
- Streaming: with fade and chunked pacing enabled, sampling the DOM during a live response showed `stream-fade` present for the whole generation and absent afterwards, and the visible character count advancing smoothly rather than in the server's 24-character bursts.
- Accent: selecting a palette in the settings panel recolours the panel immediately, and the choice survives a reload. A stale `appearance` echo in the `PUT /api/config` response was found and fixed; without it, saving reverted the just-chosen accent in the client until the next reload.
- Sidebar: collapsing animates the width (254 → 96 mid-transition → 72), and labels fade and collapse their width together. A first attempt left the hidden profile text overflowing the narrow rail; corrected.
- Reasoning: the settings editor lists no built-in Native presets and explains why, while the chat reasoning picker still offers Fast, Low, Medium and High.
- Model picker: no management shortcut; the default and unload actions are separate full pills with no mismatched corners.
- Number inputs render pill-shaped with `appearance: textfield` and no spinner buttons.
- Narrow layout at 375px: the drawer shows a close control and hides the desktop collapse control; option cards and form grids stack to one column.
- A browser default was found and fixed systemically: styled buttons that left `background` unset showed the user-agent disabled plate, visible on the disabled connection-delete control.

## Not verified

- Only Chromium was exercised. `mask-image` for the fade reveal and `rgb(var(--x) / a)` for accents are used without fallbacks; both are current baseline features but were not checked in other engines.
- Streaming was driven by a mock server, so real model pacing and tokenizer behaviour are unchanged but unmeasured.
- No real device pass; narrow-screen behaviour was checked with viewport emulation.
- The MSI was packaged without installing it or restarting the user's service. Installation and upgrade execution are not part of this validation.
