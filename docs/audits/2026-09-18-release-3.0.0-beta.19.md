# 3.0.0-beta.19 — model server enable switches, status dots, offline models in the picker

## Changes

- Connections carry an optional `disabled` flag (absent means enabled, so existing configurations are unchanged). The connection card has an enable switch to the left of the delete button. A disabled server is never probed, its models leave the chat picker, and `lib/chat-runtime.ts` refuses chat requests for them ("The selected model's server is disabled.").
- The connection list shows a small dot to the right of each server icon: green online, red offline, grey disabled. Administrators probe the unsaved draft through `POST /api/models/status` (saved keys fill in blank ones, an invalid address reports offline), debounced after edits and repeated every 15 seconds.
- Deleting a connection asks first with the `danger` message dialog; cancelling changes nothing. The deletion, like every connection edit, applies on **Save changes**.
- `GET /api/models/status` returns `statuses` (online/offline/disabled per used connection) alongside the existing `offlineConnectionIds`.
- The picker keeps offline models, greyed out and not selectable (`aria-disabled`), with the hover hint "모델을 서빙하는 서버가 오프라인입니다" / "The server serving this model is offline". The heading count is the number of online models.
- Server state is fetched on load, whenever the picker opens and every 30 seconds while the page is visible. A selection whose server is offline or disabled moves to the default model if it is online, otherwise to the first online model (`lib/model-availability.ts`). With nothing online, the model trigger reads only "서버 오프라인" / "Server offline".
- The status dot is 4.8 px and sits about 4.7 px right of the server icon (revised from 6 px touching the icon after screenshot review).
- The beta 17 integration now expects the offline model greyed out instead of hidden.
