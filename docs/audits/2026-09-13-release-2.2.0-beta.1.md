# 2.2.0-beta.1 validation

## Scope

- Replace the Browser tool's desktop headless-only execution with a visible Chromium session shared by the model and user.
- Add a top-of-chat browser control and responsive split view for direct navigation, clicking, dragging, scrolling, keyboard input, and focused-field text entry.
- Let the model explicitly hand CAPTCHA, login, or other human-only steps to the user and continue in the same browser session after confirmation.

## Architecture and safeguards

- Windows and macOS launch headed Chromium; Linux launches headed only when a display server is present and otherwise falls back to headless.
- The native Chromium window is kept off-screen because its exact page is streamed into the in-app split view, where chat and browser remain visible together.
- `GET` and `POST /api/browser-view` require authentication, conversation ownership, and an owner-bound browser session ID.
- Existing public-address validation, subresource routing checks, session limits, timeouts, and end-of-response cleanup remain active.
- The Browser tool's `request_user` action uses the existing persisted tool-input wait path. A user completion resumes the model without recreating the browser context.
