# 3.0.0-rc3-b23 — approval, artifact, plan, and storage refinements

## Scope

- Repaired the MCP approval heading layout and added a bounded, secret-aware operation explanation.
- Made artifact viewing full-screen and added Preview/Code modes for every supported artifact type.
- Added a workspace Appearance switch for model connection labels, off by default.
- Made the account plan allow-list authoritative for picker visibility and server-side inference, including administrators.
- Split storage-tool read/write permissions and added a server-enforced 1–20 text-file write cap per conversation.

## Safety notes

- MCP explanation summaries omit argument keys that look like passwords, tokens, API keys, authorization, secrets, or credentials; the existing explicit argument disclosure remains available for informed approval.
- Storage writes call the existing owner-scoped, quota-checked, atomic text-file writer and accept only `text` or `markdown` kinds.
- A direct chat request cannot bypass the plan list because `assertPlanAccess` rejects missing or unassigned models on every inference round.
- HTML artifacts remain sandboxed and code view displays source as text rather than executing it.
