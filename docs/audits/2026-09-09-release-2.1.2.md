# 2.1.2 validation

## Scope

Two presentation changes. No schema migration, no change to streaming, drivers, residency or harness behaviour. The chat wait line stops reporting a missing capability, and the driver picker explains each driver instead; the product mark is respaced.

## Automated

- Unit suite: 105 passed, including a new `lib/driver-capabilities.test.ts` covering full capability coverage per driver in both languages, the native-versus-compatible management difference, the experimental switch changing only the OpenAI-compatible progress answer, the caveat text behind a limited answer, and the flat summary naming every capability.
- Type checking: `npx tsc --noEmit` passed. Production: `npm run build` passed. `git diff --check` passed.

## Interactive

Driven in a browser against a throwaway data directory, plus a mock server for the streaming probe.

- The driver picker lists two options, each with an info marker and an `aria-describedby` summary. Hovering the marker renders the capability table: OpenAI API reports discovery supported, management limited, progress **not supported**, effort and reasoning history supported; LM Studio reports management supported and progress limited, with the caveat that a named effort level or prior reasoning proceeds without progress. Both tables render fully inside the viewport (measured), and the table is portalled to the body so the popover's own `overflow` cannot clip it.
- The settings sidebar entry for models renders the seven-node mark rather than sliders.
- The mark was blown up to 170px, 64px, 24px and 17px in the running app: nodes are separated at every size and the three layers read as layers. The favicon uses the same geometry.
- No occurrence of "진행률 미지원" or "Progress unavailable" remains in the application source, and `progressUnavailable` is gone from the client, the job type and the job snapshot.
- Streaming with progress was re-probed after editing `lib/chat-runtime.ts`, using a mock that advertises itself as an LM Studio host: progress values 0, 35, 80 and 100 arrived, phases moved preparing-response → processing-prompt, the response completed with its content, and no snapshot carried `progressUnavailable`.
- The Experimental help text no longer claims progress is "marked unavailable", since it no longer is; it now points at the driver picker.

## Not verified

- The capability table's hover was triggered through the `pointerover` event React listens for rather than a physical cursor, because the Browser pane's screenshot scale and its input coordinate frame disagree; the rendered table was confirmed visually and by measurement.
- No touch-device pass. On touch the marker responds to a tap rather than a hover, and it overlays the option's right padding.
- Progress was exercised against a mock host, not a real LM Studio instance.
- Only Chromium was exercised.
- The MSI was packaged without installing it or restarting the user's service.
