# 2.2.0-beta.2 validation

## Scope

- Add multiple tabs to the shared split-view browser, including direct user open, switch, close, navigation, and interaction controls.
- Give the model stable tab IDs plus list, open, switch, close, label, and note actions. Tab listings expose title, URL, label, note, and active state.
- Add administrator limits for browser tabs per session and questions per multiple-choice call, and apply those limits to runtime validation and generated tool schemas.
- Tighten spacing between consecutive reasoning/tool folds while retaining a slightly larger compact boundary beside response prose.
- Align persisted multiple-choice answers with the right edge used by ordinary user-message bubbles.

## Architecture and safeguards

- Each owner-bound browser session owns an ordered tab map and one active tab. The administrator limit is captured when the session starts and is enforced for model actions, user actions, and page-created popups.
- Labels and notes are session metadata. `set_tab_metadata` updates only supplied fields, and an explicit empty string clears a field.
- Existing authentication, conversation ownership, public-address checks, subresource routing checks, session TTLs, global/per-owner session caps, and end-of-response cleanup remain active.
- Existing installations gain schema defaults of 8 browser tabs and 3 multiple-choice questions; accepted administrator ranges are 1–20 and 1–10 respectively.
- Closing the last tab closes the browser session. Closing or switching a tab cannot target a tab outside the owner-bound session.
