# 3.0.0-beta.17 — usage meter, model server status, saved tool switches

## Changes

- Plan usage meters (sidebar donut and per-window bars) are white, yellow from 80% and red from 90%; each bar uses its own window's percentage.
- The usage meter reloads as soon as a chat job reaches a terminal state. The popover has a refresh button left of Close; `GET /api/usage` includes tokens from responses still streaming, tracked in a process-wide live registry. Admission and output-limit checks continue to use recorded events only.
- Streams that stop or fail after the server produced output are charged for that output; servers that omit usage are charged local estimates.
- Opening the model picker calls `GET /api/models/status`, which probes each used connection's model-list endpoint (3 s timeout, 5 s shared cache). Models on servers with transport failures or 5xx responses are hidden.
- Composer tool switches are stored per account (`enabledTools`, `PUT /api/preferences/tools`) and survive reloads and settings saves.
- Plan weights accept two decimal places (input step 0.01, server rejects a third decimal).
- Administrators can enable **Show model weights** in Appearance: models whose plan weight is not 1 show an `x<weight>` badge at the right edge with the hover text "토큰을 <weight>배 더 빨리 소모합니다". Weights are sent only to administrator accounts.
