# 3.0.0-rc1-b20 — event-driven server checks, error state, readable detection failures, storage select all

Release candidate 1 (beta 20). If QA finds no defects, only the version number changes to 3.0.0.

## Changes

- No periodic server checks. The chat picker checks `GET /api/models/status` when the workspace loads (once the real config with an account has arrived; the placeholder config is never checked), when the picker opens (not when it closes), and on the first key press after at least 60 seconds without keyboard input (`lib/use-keyboard-return.ts`, `lib/keyboard-return.ts`). The check is keyed on the connections' id/driver/baseUrl/disabled rather than the config object. The connection settings dots drop their 15 s timer and recheck on draft edits, after model detection, and on the same keyboard return.
- Server state gains `error` (`lib/connection-status.ts`): the listing endpoint answering with the expected JSON array (`data` for OpenAI, `models` for LM Studio) is `online`; any answer that is not (4xx including a rejected key, 5xx, non-JSON, wrong shape) is `error`; transport failure, timeout or an invalid URL is `offline`. Beta 17–19 counted 4xx as online and 5xx as offline. Settings dots are orange (`#f97316`) for `error`, labelled "온라인이지만 오류 발생". Picker models on an erroring server stay selectable (`selectableState` in `lib/model-availability.ts`) and are not auto-switched; they show an orange dot after the name and the hover hint "모델을 서빙하는 서버에서 오류가 발생했습니다".
- Model detection failures are classified (`lib/connection-errors.ts`: unreachable, timeout, invalid-url, unauthorized, not-found, http, server, invalid-json, invalid-shape, unexpected). `POST /api/models/detect` returns `{ error, code, status }` with 502; the settings panel shows a danger message dialog "모델 감지 실패" with a localized explanation and a detail line (connection name, address, HTTP status or the start of the body), and the footer notice reads "모델 감지에 실패했습니다.". A non-JSON reply from the app itself is also reported instead of surfacing `JSON.parse`.
- Storage manager batch mode has a "전체 선택 / 전체 해제" button. It loads up to 100 files matching the current search across pages (the batch delete limit) and says so when more exist. Deleting several files now skips files still used in chats and reports how many were skipped (they stay selected); selecting only in-use files keeps the previous behaviour of opening the related chats. Below 620 px the batch toolbar wraps its buttons under the count.
- The beta 19 integration's "down" server now resets connections instead of answering 503, since a 503 is an error state from this release.
