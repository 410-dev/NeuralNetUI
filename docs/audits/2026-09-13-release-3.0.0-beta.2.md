# 3.0.0-beta.2 validation

## Reported failure and root cause

- LM Studio rejected a browser follow-up with `request (186236 tokens) exceeds the available context size (128000 tokens)` while the pre-tool context donut showed 78,334 tokens / 61% and the configured compaction threshold was 70%.
- The next-request projection used the larger of the whole-history structural estimate and the previous server measurement. It did not add content appended after that measurement, so a new tool result could be hidden behind the 78,334-token floor.
- Browser full-page screenshots allowed up to 1440x8000 pixels, but every image was estimated as a fixed 1,600 tokens. Local multimodal tokenization can charge by image patches, making that estimate far too small.
- Page body text was capped, but interactive element labels, placeholders, and href values could still expand the serialized snapshot beyond the intended bound.
- Pre-tool compaction used response-resume compaction, which summarized away the newest tool observation instead of retaining the assistant tool request/result protocol tail.

## Corrections and safeguards

- Token projection now anchors the last server measurement to its structural estimate and adds every later assistant tool call, tool result, visual observation, and message delta.
- Browser snapshots cap both extracted body text and the complete serialized result at 32,000 characters; element text/labels/placeholders and hrefs have independent caps.
- Full-page screenshots are capped at 1440x1600 pixels. Results disclose captured dimensions, document height, and truncation so the model can scroll and inspect later sections.
- Browser images carry an internal conservative estimate of two tokens per 14x14 vision patch. The metadata is removed before OpenAI-compatible JSON is sent, while LM Studio native conversion consumes only the image file.
- Unconsumed visual-token estimates appear in the context donut's Tools category. They are marked consumed when the final follow-up inference completes, because screenshot bytes are not persisted into later conversation requests.
- Tool-round compaction summarizes prior history while retaining the newest assistant tool request, tool result, and visual observation. Previous summaries are folded into the replacement summary, and image base64 is omitted from text-only compaction input.
- Native and OpenAI-compatible context-overflow envelopes are normalized. On a known overflow with no partial output, the runtime adopts the server's reported context window, applies a measured/estimated correction factor, performs bounded compacting or rolling, and retries without re-running the tool. An overflow after partial output is never replayed.
- The retry proceeds only below a 95% corrected-input safety ceiling and uses corrected input to cap output tokens. Otherwise a localized stable error reports the known prompt/context sizes and recommends viewport capture or sectioned browsing.
