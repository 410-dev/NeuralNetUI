# 2.1.4.1 validation

## Scope

Two interface fixes on top of 2.1.4, plus the installer change a revision-only version requires. No schema migration; no change to streaming, drivers, compaction decisions or tool execution.

## Automated

- Unit suite: 113 passed. `lib/context-usage.test.ts` gained coverage for a compaction summary replacing the history it covers, for only the most recent compaction setting the boundary, and for a compaction step without a summary leaving the boundary alone.
- Type checking: `npx tsc --noEmit` passed. Production: `npm run build` passed.

## Interactive

Driven against a throwaway data directory with mock models.

- Queued messages: with a message queued while a response streamed, the composer reports `composer expanded`, `border-radius: 34px` and `padding: 14px 14px 10px`, with the queued block 590px inside a 620px form and the draft field on its own row. The pill radius no longer curves around a stacked block. With a short draft and nothing stacked it still reads `999px`, so the fix does not over-expand.
- Context donut after compaction: a 4,000-token window with a history the preview read as roughly half full was compacted at send time. The donut then read **82 / 4,000 (2.1%)** with the breakdown `입력 18 · 응답 30 · 추론 0 · 압축 요약 34` and the note "압축된 요약이 이전 대화를 대신하고 있습니다." Before the fix the same conversation kept reporting the full stored history.
- Installer: the built MSI reports ProductVersion 2.1.4.1, and its Upgrade table carries `max=2.1.4.1` with `VersionMaxInclusive` set, so an installed 2.1.4 is detected and replaced.

## Notes

- Windows Installer compares only the first three fields of a product version, so 2.1.4.1 and 2.1.4 are the same version to it. `MajorUpgrade AllowSameVersionUpgrades="yes"` is what makes the revision bump replace the installed product; without it the installer would have left 2.1.4 in place.
- `package.json` carries the four-field version. npm tolerates it for the scripts this project uses, but it is not valid semver, so publishing this package would fail. It is private and never published.
- The donut remains an estimate of the next request. It now assumes the stored summary is the one the next request will use; if history is edited, the server revalidates the summary fingerprint and may compact again, in which case the reading moves after the next turn.

## Not verified

- The compaction reading was exercised with a mock summary; real summary sizes were not measured.
- The installer was built and its tables inspected, but not executed over an existing 2.1.4 installation.
- No touch-device or non-Chromium pass.
