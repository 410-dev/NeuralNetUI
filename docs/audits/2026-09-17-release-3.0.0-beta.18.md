# 3.0.0-beta.18 — red delete prompts, in-place reset credits, model settings in personal backups

## Changes

- Chat deletion and message deletion (which also removes the connected response) confirm with the `danger` tone: red mark, rule and confirming action. Selected-chat deletion in Manage chats and in the storage reference dialog uses the same tone.
- Reset credits empty every window they cover: a covered window reports 0% with no start time until the next use, and then restarts from that first use after the reset. Longer windows keep their usage and timing. Example verified: 3 h 100%, 5 h 50%, 10 h 20% with a 5 h credit becomes 0%, 0%, 20%; the next chat starts new 3 h and 5 h windows at its own time while the 10 h window is unchanged. (An intermediate beta 18 build kept covered windows on their original timing; that was reverted at the user's request, restoring the beta 17 calculation.)
- Personal and per-user backup images carry `modelSettings`: the same `neuralnetui-model-settings` JSON as the settings download (models the owner can use, owner-visible templates, default model/template), plus `ownedModelIds` and `ownedPresets`, because the download strips ownership. The image version stays 1: the field is additive and older servers ignore it.
- Restore (`lib/model-settings-backup.ts`) runs after the data restore and never fails it:
  - Every account restores its own aliases and their templates; replace removes its aliases missing from the image. Aliases whose id belongs to another account or a served model get a deterministic `alias-<sha256(target,id)>` id; restored conversations and the default model follow it, so repeated restores stay idempotent.
  - Administrator targets also restore served-model name, description, system prompt, visibility, context length, image input settings, built-in template wording, their private templates (replace drops stale ones) and model order. Served models match by id, then served identifier; discovered capabilities are kept.
  - Models are parsed one by one with only known fields; unknown fields, future format versions, invalid entries and models this workspace does not serve are skipped and counted. Images without model settings (beta 17 and earlier) report `absent`; unreadable settings report `invalid`; a write failure reports `failed` while the data restore stands.
  - Default model/template preferences that no longer resolve are removed so the workspace default applies.
  - The restore response includes `modelSettings`, and the personal backup card shows a localized summary.
- Fixed: a standard account's templates on its own alias were saved without an owner, so the next configuration read assigned them to the superadmin and the account lost them. `writeConfigForUser` now stamps them with the account. Templates already reassigned are not recovered automatically.
