# 사용자와 권한

## 역할

| 역할 | 할 수 있는 일 |
| --- | --- |
| **superadmin** | 모든 관리 기능. 감사 권한 부여, 호스트 컴퓨터 도구 사용과 그 신뢰 정책 설정은 이 역할만 가능 |
| **admin** | 연결·모델·도구·하네스·저장소 기본값·사용자 관리. 감사 권한은 별도로 부여받아야 함 |
| **user** | 자신의 대화, 자신이 만든 커스텀 모델과 Reasoning 프리셋, 계정 설정 |

첫 접속에서 사용자 테이블이 비어 있으면 **최고 관리자 계정을 생성**합니다. 구버전에서 이관된 대화와 업로드는 이 계정에 귀속됩니다.

## 계정 관리

`설정 > 사용자`에서 관리합니다.

- 사용자 이름, 표시 이름, 비밀번호(8자 이상), 역할을 지정해 계정을 추가합니다.
- 사용자 목록은 검색 가능하고 10명 단위로 페이징되며, 계정마다 실제 저장소와 휴지통 사용량을 나란히 보여줍니다. 맨 위에는 전체 합계 카드가 있습니다.
- 계정 카드의 **관리**를 열면 표시 이름, 역할, 감사 권한, 저장소·휴지통 할당량을 한 곳에서 바꿉니다.
- 최고 관리자 계정과 현재 로그인한 본인 계정은 삭제할 수 없습니다. 본인 계정에서는 표시 이름과 역할을 이 화면에서 바꿀 수 없습니다(표시 이름은 `설정 > 계정`에서 변경).

모든 역할은 `설정 > 계정`에서 자신의 표시 이름과 비밀번호를 바꿀 수 있습니다.

## 데이터 격리

- 대화와 업로드는 사용자별로 완전히 분리되며, 다른 사용자의 데이터에 대한 API 접근은 거부됩니다.
- 커스텀 모델은 만든 사용자에게만 보입니다. **커스텀 모델 공개**를 켜면 다른 사용자도 채팅에서 쓸 수 있지만 수정할 수는 없습니다.
- 커스텀 Reasoning 프리셋도 같은 규칙을 따릅니다.
- 서빙 모델과 그 Reasoning 템플릿은 관리자 소유입니다. 일반 사용자에게는 해당 컨트롤이 숨겨지는 대신 **비활성 상태로 보입니다**.
- 일반 사용자의 설정 화면은 일반, 모양, 모델(자신의 alias), 추론(자신의 프리셋), 계정 탭만 제공합니다.

## 감사

감사 권한은 **Superadmin만** 부여할 수 있고, admin 역할에만 줄 수 있습니다. 감사 관련 API 라우트는 이 권한을 요구합니다.

감사 권한이 있는 관리자는 계정 관리 화면에서 대상 사용자의 데이터를 열람할 수 있습니다.

| 기능 | 설명 |
| --- | --- |
| 대화 열람 | 20개 단위 페이징. 앱 안에서 전체 브랜치를 그대로 검토 |
| 대화 검색 | ID·제목·모든 브랜치 내용을 검색. 페이지당 최대 10건 |
| 대화 내보내기 | 전체 브랜치를 ZIP으로 내보내기 |
| 파일 열람 | 24개 단위 페이징, 썸네일·목록 레이아웃, 이름·크기·생성일 정렬, 다운로드 |
| 휴지통 | 소프트 삭제된 대화·파일의 복원과 영구 삭제 |

감사 열람에서 첨부 URL은 감사가 기록되는 대상 사용자 엔드포인트로 다시 쓰입니다. 모든 감사 행위는 `admin_audit_log` 테이블에 남습니다.

## 워크스페이스 기본값

관리자는 모델·Reasoning 선택기의 **전체 적용**으로 워크스페이스 기본값을 정할 수 있습니다. 이 동작은 지정한 키 하나만 모든 계정에 덮어쓰므로, 각 사용자의 나머지 설정은 그대로 유지됩니다.

로그인 화면의 액센트 색(`loginAppearance`)도 워크스페이스 설정입니다. 로그인 전에는 읽을 계정이 없으므로 비인증 엔드포인트를 통해 전달됩니다.

## 세션과 비밀번호

- 로그인 세션은 SQLite `sessions` 테이블에 저장되고 쿠키로 유지됩니다.
- 비밀번호 변경은 `설정 > 계정`에서 하며, 최소 8자입니다.
- 저장된 API 키는 어떤 역할에게도 브라우저 응답으로 돌아가지 않습니다.
