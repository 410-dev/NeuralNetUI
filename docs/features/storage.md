# 개인 저장소

모든 첨부와 업로드는 **계정 소유의 개인 저장소**에 들어갑니다. 다른 사용자는 목록에서도 볼 수 없고 API로도 접근할 수 없습니다.

## 파일이 들어오는 경로

| 경로 | 설명 |
| --- | --- |
| 채팅 첨부 | 입력창에 끌어다 놓거나 붙여넣은 이미지·PDF·파일 |
| 직접 업로드 | 저장소 화면에서 여러 파일을 한 번에 업로드 |
| 파일 생성 | 저장소 화면에서 Markdown 또는 텍스트 파일을 직접 작성. GFM·KaTeX 미리보기 제공 |
| 도구 산출물 | 브라우저·호스트 스크린샷, 호스트 `store_file`로 가져온 파일 |

브라우저 업로드는 인증된 8 MiB 청크로 나뉘어 전송되고 제한된 횟수만큼 재시도합니다. 덕분에 어떤 요청도 Cloudflare Tunnel의 100 MB 제한 같은 상한에 근접하지 않습니다. 서버는 완료 시 모든 조각과 최종 크기를 검증한 뒤에야 파일을 원자적으로 등록합니다.

## 저장 방식

- 메타데이터와 메시지 연결은 SQLite에, 파일 본문은 `data/uploads`에 둡니다.
- 이미지는 원본을 그대로 보존하고, 목록에는 브라우저가 만든 경량 썸네일을 씁니다.
- PDF는 원본과 제한된 텍스트 추출 캐시만 보관합니다. 텍스트가 없는 스캔 PDF는 모델 요청 시 제한된 페이지를 임시 이미지로 렌더링한 뒤 즉시 삭제합니다.
- 인증이 필요한 파일 응답은 `no-store`로 내려가므로, 브라우저 캐시가 다른 계정에서 재사용되지 않습니다.
- 시그니처로 확인된 래스터 이미지와 PDF만 인라인 표시하고, 그 외 타입은 다운로드됩니다.

## 저장소 화면

사이드바의 저장소 버튼으로 엽니다.

- 화면 크기에 맞춰 3~7행의 2열 격자로 표시됩니다.
- 파일 이름 실시간 검색, 이름·크기·생성일 정렬, 페이지네이션을 지원합니다.
- 용량 미터가 실제 저장소와 휴지통 사용량을 각각 보여줍니다.
- 원형 체크 표시를 사용하는 선택 모드로 여러 파일을 한 번에 다룰 수 있습니다. 같은 선택 UI를 채팅 첨부 선택기에서도 씁니다.

### 참조 보호와 삭제

- 활성 대화에서 참조 중인 파일은 사용자 삭제로부터 보호됩니다. 이미 삭제된 대화의 참조는 보호 근거가 되지 않습니다.
- 참조된 파일을 지우려 하면, 그 파일을 쓰는 활성 대화 목록이 열립니다. 거기서 해당 대화로 이동하거나, 선택한 대화를 지우거나, **관련 대화와 파일을 한꺼번에** 원자적으로 삭제할 수 있습니다.

## 할당량

| 항목 | 기본값 | 범위 |
| --- | --- | --- |
| 계정별 저장소 할당량 | 512 MB | 1 MB ~ 10 TB |
| 계정별 휴지통 할당량 | 1 GB | 1 MB ~ 20 TB |
| 휴지통 보존 기간 | 60일 | 1 ~ 60일 |

- 관리자는 `설정 > 도구`의 저장소 영역에서 **워크스페이스 기본값**을, `설정 > 사용자`에서 **계정별 값**을 정합니다.
- 계정 할당량을 `0`으로 저장하면 워크스페이스 기본값을 상속하고, 이후 기본값이 바뀌면 계속 따라갑니다. 새 계정은 두 기본값을 모두 상속합니다.
- 할당량 예약과 축소는 원자적 SQLite 트랜잭션으로 직렬화됩니다.
- 현재 사용량보다 낮은 기본값은 저장이 거부됩니다(어느 계정이 걸렸는지 알려줍니다).

## 휴지통

사용자에게 보이는 대화·파일 삭제는 **소프트 삭제**입니다.

- 보존 기간 동안 휴지통에 남고, 휴지통 용량을 넘기면 오래된 것부터 정리됩니다.
- 일반 사용자는 휴지통을 열거나 그 안의 파일을 가져올 수 없습니다.
- 감사 권한을 가진 관리자만 복원하거나 영구 삭제할 수 있습니다([사용자와 권한](users.md#감사) 참고).

## 미첨부 업로드 정리

대화에서 참조되지 않은 업로드는 설정된 보관 시간(`orphanUploadTtlHours`, 기본 24시간)이 지난 뒤 다음 업로드 요청에서 정리됩니다. 도구가 만든 보존 대상 이미지는 이 정리에서 제외됩니다.
