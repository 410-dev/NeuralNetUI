# 모델과 연결

## 연결

`설정 > 연결`에서 추론 서버를 여러 개 등록합니다. 각 연결은 드라이버 하나를 고릅니다.

| 드라이버 | 기본 주소 | 모델 목록 | 채팅 | 로드/언로드 |
| --- | --- | --- | --- | --- |
| OpenAI API | `http://localhost:8888/v1` | `/models` | `/v1/chat/completions` 스트림 | LM Studio 관리 API를 먼저 시도하고, 없으면 `/api/inference` |
| LM Studio | `http://localhost:1234` | `/api/v1/models` | 네이티브 SDK 추론, 미지원 요청은 `/v1/chat/completions` | `/api/v1/models/load`, `/unload` |
| NNUI Server | `http://127.0.0.1:11435` | `/v1/models` | `/v1/chat/completions` 스트림과 대화별 세션 고정 | `/api/models/status`, `/{id}/load`, `/{id}/unload` |

LM Studio 채팅은 도구 호출과 전체 대화 이력을 보존해야 하는 경우 호환 스트림을 사용합니다. 명명된 reasoning effort와 이전 추론 분리 전달은 SDK 1.5.0이 표현할 수 없어 Chat Completions 경로를 유지합니다.

NNUI Server 드라이버는 Base URL에 `/v1`을 쓰지 않아도 자동으로 공개 API 경로를 구성합니다. 각 대화의 안정적인 ID를 `X-Llama-NNUI-Session-Id`로 보내 같은 llama.cpp 슬롯과 prompt prefix를 재사용하고, Bearer 키가 설정돼 있으면 모델·관리·이벤트 API 모두에 같은 키를 사용합니다.

### 우선순위

- 연결 카드는 드래그하거나 위/아래 버튼으로 정렬합니다.
- 같은 모델 identifier가 여러 서버에 있으면 **가장 위 연결**이 선택됩니다.
- 정규화한 서버 루트가 같은 연결끼리는 admission 상태를 공유하고, 설정 중 가장 엄격한 값을 따릅니다.

### 연결별 저장

감지된 모델, 표시 여부, 설명, 시스템 프롬프트, 컨텍스트 길이, Reasoning 프리셋은 모두 연결별로 저장됩니다. 다른 서버를 쓰다가 돌아와도 그대로 복원됩니다.

## 모델 감지와 관리

감지 버튼을 누르면 서버가 반환한 모델이 `설정 > 모델`의 관리 목록에 **전부** 보존됩니다.

감지에 실패하면 빨간색 **모델 감지 실패** 창이 원인과 확인할 점을 알려 줍니다. API 키 거부(401/403), 모델 목록 주소 없음(404), 서버 내부 오류(5xx), JSON이 아닌 응답(예: 로그인 페이지나 `/v1`이 빠진 주소), 모델 목록 형식이 아닌 응답, 연결 불가, 시간 초과, 잘못된 URL을 구분합니다. 창 아래쪽에는 연결 이름·주소와 서버가 실제로 보낸 응답(HTTP 상태 또는 응답 앞부분)이 표시되고, 설정 창 하단에는 "모델 감지에 실패했습니다."가 남습니다. 감지 후에는 연결 상태 점도 다시 확인합니다.

| 항목 | 설명 |
| --- | --- |
| 메인 인터페이스에 표시 | 끄면 모델 선택기와 Reasoning 설정 목록에서만 숨깁니다. 관리 목록에는 남습니다 |
| 설명 | 모델 선택기에 표시되는 한 줄 설명 |
| 시스템 프롬프트 | 이 모델로 보낼 때 앞에 붙는 지시 |
| 컨텍스트 길이 | 사용자가 지정한 값. API가 알려준 값(`apiContextWindowTokens`)과 별도로 저장되어 감지로 덮어써지지 않습니다 |
| 이미지 입력 | 아래 참고 |

숨긴 서빙 모델은 커스텀 alias의 기반 모델 선택 목록에서도 제외됩니다.

채팅 모델 선택기는 현재 계정 플랜의 `servedModelIds`에 모델 ID 또는 기반 모델 ID가 명시된 모델만 표시합니다. 이 규칙은 관리자와 슈퍼 관리자에게도 같으며, 빈 목록은 사용할 수 있는 모델이 없다는 뜻입니다. 서버의 채팅 실행 경로도 같은 규칙을 다시 검사하므로 클라이언트 요청을 직접 바꿔 우회할 수 없습니다.

### 이미지 입력

모델 카드의 **이미지 입력** 그룹은 입력란과 스위치 한 줄로 되어 있습니다.

| 모드 | 동작 |
| --- | --- |
| 원본 (기본) | 저장된 원본을 그대로 모델에 전달 |
| 최대 해상도 | 설정한 긴 변 픽셀 한도(128~8192, 기본 1024)로 JPEG 캐시를 만들어 전달 |

원본 파일은 어느 모드에서도 저장소에서 변경되지 않습니다. alias가 가진 이미지 설정은 기반 서빙 모델의 설정을 덮어씁니다. 큰 이미지에서 종료되는 모델이 있다면 이 값을 낮추세요.

## 커스텀 모델 (alias)

커스텀 모델은 별도 모델을 복제하지 않는 **alias**입니다.

- 표시 이름, ID, 시스템 프롬프트만 독립적으로 가지며, 요청은 기반 모델의 ID로 전송됩니다.
- 만든 사용자에게만 보입니다. **커스텀 모델 공개**를 켜면 다른 사용자도 채팅에서 쓸 수 있지만 수정할 수는 없습니다.
- 서빙 모델(그리고 그 Reasoning 템플릿)은 관리자의 것입니다. 일반 사용자는 서빙 모델을 자신의 기본값으로 지정할 수는 있어도 프롬프트나 템플릿을 고칠 수 없으며, 자신이 만든 alias는 완전히 편집할 수 있습니다.

## 모델 로드와 상주 관리

여러 사용자가 한 추론 서버를 공유할 때 메모리를 관리하는 기능입니다.

| 설정 | 위치 | 의미 |
| --- | --- | --- |
| On demand | `설정 > 일반` | 각 추론 요청 전에 드라이버에 맞는 load API를 호출 |
| `maxResidentModels` | 연결별 | 0은 무제한. 양수면 On demand가 꺼져 있어도 관리형 로딩이 활성화 |
| `modelWaitPolicy` | 연결별 | `capacity`(여유 생길 때까지 대기) 또는 `serial`(한 번에 하나) |

On demand로 로드할 때 OpenAI 드라이버의 `repo:variant` 형식 ID는 `model_path`와 `gguf_variant`로 나뉘어 전송되고, LM Studio에는 `model`과 선택적 `context_length`가 전송됩니다. NNUI Server는 등록된 모델 ID를 URL path에 넣어 load/unload를 호출하며, 모델 설정은 NNUI 제어면의 등록값을 사용합니다.

### admission과 축출

- 서버 전역 residency 관리자가 재고 확인과 로드/언로드 변경을 직렬화합니다. alias는 기반 모델을 기준으로 판단합니다.
- 서버·모델별 LFU 사용 횟수와 마지막 사용 시각이 DB에 기록됩니다. 축출 대상은 유휴 모델 그룹 중 사용 횟수가 가장 적은 것, 같으면 가장 오래 쓰지 않은 것입니다. 로드된 인스턴스가 여러 개면 각각 상한에 포함됩니다.
- 대기 중인 admission은 취소할 수 있습니다. 실행 중인 작업은 도구 라운드와 사용자 입력 대기를 거치는 동안 자신의 모델을 유지합니다.
- 연결 거부와 DNS 실패만 최대 30초까지 재시도합니다. 원인이 모호한 추론 실패는 재전송하지 않습니다.

### 언로드

관리자는 모델 선택 메뉴의 **로드된 모델 언로드**로 서버의 현재 추론 모델을 메모리에서 내릴 수 있습니다. 이 버튼은 **생성 중에도** 동작합니다. 서버 부하를 줄이는 쪽을 우선한 의도된 동작이며, 해당 모델을 쓰는 생성은 서버 응답에 따라 중단되거나 오류로 끝날 수 있습니다.

## 서버 상태

서버 상태는 주기적으로 확인하지 않습니다. 화면을 불러올 때, 모델 선택 메뉴를 열 때, 1분 넘게 키보드 입력이 없다가 다시 입력할 때만 서버가 각 연결의 모델 목록 엔드포인트를 3초 제한으로 확인합니다. 결과는 5초간 재사용하며, 메뉴에서 확인하는 동안에는 개수 대신 진행 표시가 나타납니다.

- 모델 목록을 정상 JSON으로 돌려주면 **온라인**, 응답은 하지만 오류(API 키 거부 등 4xx, 5xx, JSON이 아닌 응답, 모델 목록이 아닌 응답)이면 **오류**, 연결할 수 없거나 시간 초과면 **오프라인**입니다.
- 오류 상태 서버의 모델은 선택할 수 있으며, 모델 이름 옆에 주황색 점이 붙고 마우스를 올리면 "모델을 서빙하는 서버에서 오류가 발생했습니다"가 나타납니다.

- 오프라인 서버에 속한 모델(그 서버를 쓰는 alias 포함)은 회색 글자로 표시되고 선택할 수 없습니다. 마우스를 올리면 "모델을 서빙하는 서버가 오프라인입니다"가 나타납니다. 메뉴의 개수는 온라인 모델 수입니다.
- 선택된 모델의 서버가 오프라인이 되면 기본 모델(온라인일 때) 또는 첫 번째 온라인 모델로 자동으로 바뀝니다.
- 온라인 모델이 하나도 없으면 모델 선택 버튼에 "서버 오프라인"만 표시됩니다.
- 관리자가 **연결** 탭에서 끈 서버의 모델은 메뉴에서 빠지고, 서버는 그 모델로 들어온 채팅 요청을 거부합니다.

**연결** 탭의 서버 목록은 서버 아이콘 오른쪽의 작은 점으로 상태를 보여 줍니다. 초록색은 온라인, 주황색은 온라인이지만 오류 발생, 빨간색은 오프라인, 회색은 비활성화입니다. 저장하지 않은 주소 변경은 바로 확인하고, 모델 감지 후와 1분 넘게 키보드 입력이 없다가 다시 입력할 때 다시 확인합니다. 상세 설정의 삭제 버튼 왼쪽 스위치로 연결을 켜고 끄며, 삭제 버튼은 빨간색 확인 창을 띄웁니다. 변경은 **변경사항 저장** 후 적용됩니다.

## 기본 선택

| 조작 | 범위 |
| --- | --- |
| 모델·Reasoning 선택기의 **기본으로 사용** | 내 계정의 다음 접속 초기값 |
| 그 옆의 **전체 적용** (관리자) | 워크스페이스 기본값으로 저장하고 모든 계정의 해당 키 하나만 덮어씀 |

**전체 적용**은 지정한 키 하나만 덮어쓰므로, 각 사용자의 다른 설정은 그대로 남습니다. 기존 대화에서 **새 채팅**을 누르면 현재 선택이 유지됩니다.

## 진행률 표시

- LM Studio 연결은 요청 범위의 `@lmstudio/sdk`에서 실제 모델 로드·프롬프트 처리 진행률을 받아옵니다. 표시 방식(텍스트/퍼센트/도넛/둘 다)은 `설정 > 모양`에서 고릅니다.
- NNUI Server 연결은 인증된 `/api/events` SSE에서 `model.load.progress`와 `request.prefill.progress`를 읽습니다. 이벤트 스트림이 끊겨도 채팅은 계속되며 최종 모델 상태는 `/api/models/status`를 기준으로 확인합니다.
- 프롬프트 처리 퍼센트는 짧은 스트림 공백 동안에도 유효한 값으로 유지되며, 30초 동안 서버 응답이 없을 때만 "서버 대기"로 바뀝니다.
- `설정 > 실험실`의 **openAIProgress**(관리자, 기본 꺼짐)를 켜면 OpenAI 드라이버 연결도 같은 서버의 LM Studio 네이티브 재고를 먼저 조회합니다. 그 외 호스트는 표준 Chat Completions로 동작하며 진행률은 제공되지 않습니다. 일반 토큰 사용량을 프롬프트 처리율로 해석하는 일은 없습니다.

## 설정 내보내기·가져오기

`설정 > 일반`에서 모델, alias, 표시 여부, Reasoning 프리셋, 기본 선택을 JSON으로 내보내고 되돌릴 수 있습니다. 개인 백업 이미지에도 같은 모델 설정이 포함되어 복원됩니다. 자세한 내용은 [설정 파일과 환경 변수](../configuration.md#설정-내보내기와-가져오기)를 참고하세요.
