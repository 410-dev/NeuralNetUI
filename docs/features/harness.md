# 하네스와 컨텍스트

하네스는 모델 요청 바깥에서 대화를 관리하는 계층입니다. `설정 > 도구`에서 관리자가 설정합니다.

## 컨텍스트 사용량 표시

입력창의 도넛은 다음 요청이 소모할 것으로 **추정되는** 입력 토큰을 보여줍니다.

- 대화 이력, 작성 중인 초안, 첨부, 도구 컨텍스트를 모두 포함하며 입력·응답·추론으로 나누어 표시합니다.
- 도구 정의(모델에 제공한 함수 설명과 입력 형식)도 매 요청에 들어가므로, 가장 최근 응답의 마지막 요청이 보낸 크기를 **도구 정의**로 따로 표시하고 합계에 넣습니다(마이그레이션 36). 응답이 하나도 없으면 0입니다.
- 구조적 추정치가 실제 토크나이저 청구량보다 낮게 나올 수 있어, 서버가 알려준 마지막 실측값을 바닥으로 삼고 그 이후 추가분을 더한 값을 씁니다.
- 압축이 일어나면 도넛은 **가장 최근 압축 지점부터** 세고, 요약이 덮는 이력 대신 요약을 계산에 넣습니다. 그래서 압축 효과가 도넛에 즉시 보입니다.
- 추론 재전송 토글을 바꾸면 즉시 반영됩니다.

컨텍스트 압축이나 롤링은 실제 상위 입력을 더 줄일 수 있으므로, 화면 문구는 항상 "추정"이라고 밝힙니다.

## 컨텍스트 모드

| 모드 | 동작 |
| --- | --- |
| **rolling** (기본) | 컨텍스트가 넘칠 때 가장 오래된 턴부터 잘라냅니다. 최신 턴 하나가 이미 한도를 넘으면 오류로 알립니다 |
| **compacting** | 임계값에 도달하면 이전 대화를 요약으로 대체합니다. 최근 **그대로 유지할 최근 대화**(기본 3쌍)의 질문·답변과 지금 보내는 요청은 요약하지 않고 원문 그대로 둡니다 |

기본 처리 방식(롤링·압축)과 별개로 **세부 내용 먼저 버리기**를 켤 수 있습니다. 켜면 임계값에서 먼저 도구 내용과 추론을 버리고, 그래도 임계값을 넘을 때만 기본 처리 방식이 폴백으로 이어집니다.

압축, 세부 내용 버리기, 폴백 롤링이 일어나면 전사의 단계 옆에 **절약한 토큰 수**(예: `50k 토큰 절약됨`)가 표시됩니다. 줄이기 전과 후의 모델 입력을 같은 방식으로 추정해 뺀 값입니다.

### 압축

| 설정 | 기본값 | 범위 |
| --- | --- | --- |
| 압축 임계값 | 80% | 10 ~ 95% |
| 압축 모델 | 현재 대화의 기반 모델 | 비우면 기반 모델 |
| 압축 추론 강도 | off | — |
| 압축 프롬프트 | 내장 요약 지시 | 최대 32,000자 |
| 압축 프롬프트 위치 | 대화 내용 뒤 | 뒤 / 앞(시스템 프롬프트) |

압축 프롬프트는 기본적으로 **대화 내용 뒤**에 붙어 하나의 사용자 메시지로 갑니다. 위치를 **앞**으로 바꾸면 예전처럼 시스템 프롬프트로 보내고 대화 내용은 사용자 메시지로 보냅니다. 프롬프트에 `{CHAT_CONTENT}`를 쓰면 위치 설정과 관계없이 그 자리에 대화 내용이 들어갑니다(여러 번 써도 모두 치환).

동작 방식:

- 압축 여부는 **추정치와 실측치 중 큰 값**으로 판단하며, 전송 직전과 스트리밍 도중 모두 확인합니다.
- 스트리밍 중에는 전달된 본문, 추론, 도구 인자를 SSE 이벤트 단위로 검사합니다.
- 요청 범위 AbortController가 추론만 중단하고 작업 자체는 취소하지 않습니다. 요약 동안 모델 상주 잠금을 반납했다가 재개할 때 다시 얻습니다.
- 도구 라운드 압축은 가장 최근 도구 요청·관찰을 유지하고, 텍스트 전용 요약에서는 이미지 페이로드를 제거합니다.
- 부분적으로 도착한 도구 호출은 **실행하지 않고** 데이터로만 요약합니다.
- 요약 요청은 직렬화된 이력이 너무 클 때 여러 조각으로 나누며, 각 조각에 이전 요약을 포함합니다.
- 브랜치 요약은 별도로 저장되고 SHA-256 지문으로 원본 이력을 검증한 뒤에만 재사용됩니다. 원본 메시지는 그대로 남습니다.
- 압축 단계는 대기 상태가 `compacting-context`로 바뀔 때 전사에 열리고, 완료 시 그 자리에서 요약·추론으로 채워집니다.

### 세부 내용 먼저 버리기

기본 처리 방식 위에 얹는 단계입니다. 압축과 같은 임계값(10 ~ 95%, 기본 80%)을 씁니다. 요약 모델을 부르지 않으므로 빠르고 비용이 없지만, 버린 도구 결과의 내용은 모델이 더 이상 볼 수 없습니다.

- **전송 직전**: 이번 요청의 사용자 메시지 앞까지 모든 도구 호출, 도구 결과, 도구가 돌려준 이미지, 추론을 버립니다. 도구 호출만 있던 빈 응답은 통째로 빠지고, 이어진 응답 텍스트는 하나로 합쳐 역할 순서를 지킵니다. 어디까지 버렸는지는 브랜치의 컨텍스트 상태에 저장되어 다음 요청에도 그대로 적용됩니다.
- **응답 도중(도구 라운드)**: 가장 최근 도구 요청과 그 결과는 남기고 그 이전 라운드만 버립니다.
- **폴백**: 버린 뒤에도 임계값을 넘으면 기본 처리 방식이 이어집니다. 롤링이면 임계값 아래로 내려갈 때까지 가장 오래된 턴을 빼고(저장하지 않고 요청마다 계산), 압축이면 요약해 저장합니다.
- **생성 도중**: 출력이 임계값에 닿으면 생성을 멈추고 먼저 세부 내용(이전 도구 호출·결과·추론)을 버립니다. 지금까지 쓴 답변은 텍스트로 남기고 모델에게 이어 쓰라고 요청합니다. 그래도 넘치면 압축 모드는 요약 후 재개, 롤링 모드는 오래된 턴을 빼고 이어 씁니다. 롤링 모드도 세부 내용 버리기가 켜져 있으면 스트리밍 중 임계값을 감시합니다.
- 상위 서버가 컨텍스트 초과를 알리면 같은 순서로 줄인 뒤 재시도합니다.

### 브랜치의 컨텍스트 상태

모델에게 보내는 내용은 브랜치마다 저장된 **컨텍스트 상태**로 정해집니다(`context_states` 테이블, 마이그레이션 27).

| 항목 | 의미 |
| --- | --- |
| 요약 | 어느 메시지까지를 요약이 대신하는지와 요약 텍스트 |
| 세부 내용 버림 | 어느 메시지까지 도구 내용과 추론을 빼는지 |
| 컨텍스트 편집 | 컨텍스트 보기에서 고친 메시지별 내용(텍스트, 추론, 도구 인자·결과, 빼기) |

- 메시지는 순서가 아니라 ID로 가리키므로, 앞쪽 메시지를 제자리에서 고쳐도 요약이 풀리지 않습니다. 가리키던 메시지가 지워지면 그 항목은 무시됩니다.
- 새 브랜치(포크)는 자기 상태가 생기기 전까지 부모 브랜치의 상태를 따릅니다. 포크에 없는 메시지를 가리키는 항목은 적용되지 않습니다.
- 예전 방식으로 저장된 요약(`context_summaries`)은 처음 읽을 때 새 형식으로 바뀝니다.
- 백업과 복원에 함께 포함됩니다.

### 수동 압축 (`/compact`)

입력창에 정확히 아래 형태만 입력하면 메시지를 보내지 않고 지금 바로 컨텍스트를 줄입니다. 다른 글자가 붙거나 문장 중간에 있으면 평소처럼 모델에게 보냅니다.

| 명령 | 동작 |
| --- | --- |
| `/compact` | 설정된 방식대로 줄입니다. 세부 내용 먼저 버리기가 켜져 있거나 기본 방식이 롤링이면 마지막 메시지까지 세부 내용을 버리고, 기본 방식이 압축이면(버리기로 임계값 아래가 되지 않았을 때) 요약합니다 |
| `/compact summarize` | 설정과 관계없이 마지막 메시지까지 요약합니다 |

`/`를 입력하면 입력창 바로 위에 명령 자동 완성이 뜨고, 입력할수록 맞는 명령만 남습니다(↑↓로 고르고 Tab 또는 Enter로 채우며 Esc로 닫습니다). 입력이 명령과 정확히 맞으면 글자가 연한 파란색으로 바뀌고, 뒤에 다른 글자가 붙어 메시지로 간주되면 원래 색으로 돌아갑니다. 명령 목록은 `lib/compact-command.ts`의 `SLASH_COMMANDS`에 있습니다.

실행하면 대화 끝에 사고 블록과 같은 모양의 압축 블록이 열려 `n초 동안 압축 중`으로 시간을 세고, 요약할 때는 모델의 사고와 요약이 생성되는 대로 흘러나옵니다. 끝나면 `n초 동안 압축 완료 (x 토큰 절약됨)`으로 바뀌어 마지막 응답에 남고, 결과는 컨텍스트 상태에 저장됩니다. 세부 내용만 버린 경우도 같은 표시를 씁니다. 요약은 모델을 호출하므로 토큰 사용량에 포함됩니다. 응답을 생성하는 동안에는 실행할 수 없습니다.

### 재개

압축 후 중단된 응답을 이어 쓰게 하는 설정입니다.

| 설정 | 기본값 | 범위 |
| --- | --- | --- |
| 재개 프롬프트 | 내장 지시 | 최대 32,000자 |
| 최대 재개 횟수 | 3 | 0 ~ 100 |

재개 프롬프트에는 두 자리 표시자를 한 번씩 쓸 수 있습니다.

| 표시자 | 치환 내용 |
| --- | --- |
| `%COMPRESSED%` | 압축 요약 |
| `%USER_PROMPT%` | 원래 사용자 요청 |

재개 횟수는 응답 하나 기준이며, 전송 전 압축은 세지 않습니다. 재개 재시도는 도구 라운드를 소모하지 않습니다. 원본 프롬프트·첨부와 이미 보인 부분 출력은 유지됩니다. 압축 후에도 입력이 불가능하면 전송 전에 실패로 처리합니다.

### 컨텍스트 초과 복구

상위 서버가 컨텍스트 초과를 알리면, 제한된 범위의 압축을 한 뒤에만 재시도합니다. 보정한 요청이 여전히 안전 상한(95%)을 넘으면, 보고된 토큰 수와 함께 지역화된 안정적인 오류를 사용자에게 보여주고 뷰포트·구간 단위 열람을 권합니다. 브라우저 스냅샷의 32,000자 상한과 전체 페이지 캡처 상한도 같은 문제를 예방하기 위한 장치입니다.

## 응답 길이

`maxOutputTokens`는 한 응답이 생성할 수 있는 토큰 상한입니다. `0`이면 남은 컨텍스트 창 전체를 씁니다(기본값). 범위는 0 ~ 1,000,000입니다.

## 제목 생성

| 설정 | 기본값 |
| --- | --- |
| 사용 여부 | 꺼짐 |
| 시점 | 응답 후 (`before` / `after`) |
| 모델 | 현재 대화의 기반 모델 |
| 추론 강도 | off |
| 프롬프트 | 내장 지시 |

켜면 첫 턴에서 대화 제목을 자동으로 만듭니다. 하네스 요청은 상주 잠금을 독립적으로 얻고 반납하므로, serial 정책에서도 교착이 생기지 않습니다.

## 반복 출력 감지

작은 모델은 같은 내용을 끝없이 되풀이할 수 있습니다. 서버는 응답이 스트리밍되는 동안 추론, 응답 본문, 도구 호출(스트리밍 중인 인자 포함)을 살펴, 같은 단위가 **연속으로** 정해진 횟수 이상 나오면 입력창 위에 MCP 승인과 같은 형식의 **반복 출력 감지** 알림을 띄웁니다.

| 종류 | 기본 횟수 | 판단 기준 |
| --- | --- | --- |
| 단어 | 20회 | 공백으로 나눈 같은 단어(앞뒤 문장 부호 제외) |
| 문장 | 5회 | 마침표·물음표·느낌표 또는 줄바꿈으로 나눈 같은 문장 |
| 문단 | 5회 | 빈 줄로 나눈 같은 문단. 같은 도구 호출(이름과 인자가 같음)이 연달아 나오는 것도 포함 |
| 문단 묶음 | 2회 | 문단 2~12개가 한 묶음으로 반복. 도구 호출 묶음의 반복도 포함 |

- 알림의 **정지하기**는 응답을 바로 멈추고, **다시 시도하기**는 멈춘 뒤 같은 요청에 대한 응답을 새 리비전으로 다시 생성하며, **무시하기**는 알림만 닫습니다. 무시한 반복이 계속 길어져도 같은 알림은 다시 뜨지 않고, 다른 반복이 생기면 새로 알립니다.
- 각 스트림의 끝부분(최근 약 24,000자)만 검사하며, 너무 짧은 줄(코드의 닫는 괄호처럼 8자 미만인 문장, 16자 미만인 문단)은 세지 않습니다.
- `설정 > 하네스 설정 > 반복 출력 감지`에서 종류별로 켜고 끄고 횟수를 바꿀 수 있습니다.

## 도구와 파일 한도

| 항목 | 기본값 | 범위 |
| --- | --- | --- |
| 최대 도구 라운드 | 8 | 1 ~ 10,000 |
| 호출당 선택형 질문 | 3 | 1 ~ 10 |
| 메시지당 첨부 | 12 | 1 ~ 50 |
| 텍스트 다운로드 한도 | 1 MB | 0.0625 ~ 10 MB |
| 텍스트 글자 수 한도 | 24,000 | 1,000 ~ 1,000,000 |
| 이미지 다운로드 한도 | 10 MB | 1 ~ 50 MB |
| 이미지 업로드 한도 | 20 MB | 1 ~ 50 MB |
| PDF 용량 한도 | 25 MB | 1 ~ 100 MB |
| PDF 페이지 한도 | 100 | 1 ~ 500 |
| PDF 추출 글자 수 | 100,000 | 1,000 ~ 1,000,000 |
| PDF 비전 페이지 수 | 6 | 0 ~ 20 |
| PDF 처리 제한 시간 | 30초 | 5 ~ 120초 |
