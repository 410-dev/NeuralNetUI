# Reasoning

## 프리셋 종류

`설정 > 추론`에서 모델별 Reasoning 템플릿을 관리합니다. 서버가 알려준 옵션으로 프리셋을 자동 생성하지 않습니다(이전의 Built-in Fast/Thinking/Default는 제거되며, 저장된 것도 정규화 시 사라집니다). 채팅의 추론 선택기에는 템플릿만 표시되고, 템플릿이 하나도 없는 모델은 `reasoning_effort` 없이 모델 자체 기본 추론으로 동작합니다(선택기에는 템플릿이 없다는 안내만 보이며, 시스템 프롬프트 편집은 그대로 쓸 수 있습니다).

alias에 (보는 사람이 쓸 수 있는) 템플릿이 하나도 없으면 현재 기반 모델의 템플릿 목록을 그대로 상속합니다. 채팅에서 기반 모델을 바꾸면 추론 선택기의 목록도 그 기반 모델의 것으로 바뀌고, 고른 템플릿이 새 목록에 없으면 계정 기본 강도 또는 맨 위 템플릿으로 돌아갑니다. 상속은 실행 시점에만 적용되므로 alias 설정에 템플릿이 복사되지 않으며, alias에 템플릿을 하나라도 추가하면 그 alias의 템플릿만 보입니다.

템플릿은 이름이 레이블이고, **설명**을 적으면 채팅의 추론 선택 창에서 이름 아래에 그 문구가 표시됩니다(비우면 API 값에 맞는 추론 강도 설명, 최대 200자). 템플릿은 직접 입력한 **API로 전송할 값**을 그대로 `reasoning_effort`로 전달한 뒤(비우면 생략), 템플릿 내용을 모델/alias 시스템 프롬프트와 조합합니다.

커스텀 템플릿의 시스템 프롬프트는 세 가지 방식으로 모델 프롬프트와 합쳐집니다.

| 모드 | 결과 |
| --- | --- |
| `replace` | 모델 프롬프트를 템플릿으로 대체 |
| `prepend` | 템플릿을 앞에 붙임 |
| `append` | 템플릿을 뒤에 붙임 (기본) |

템플릿의 공개 범위는 **Global** / **Private** 토글로 정하며 관리자에게만 보입니다(기본 Private).

- **Private**: 만든 사람에게만 보입니다.
- **Global** (`global: true`): 그 모델을 쓸 수 있는 모든 계정에 보입니다. 관리자만 만들거나 수정·삭제할 수 있고, 다른 관리자가 수정해도 작성자는 유지됩니다. 작성자 계정을 삭제해도 남습니다. 일반 계정이 보낸 `global` 값은 서버에서 무시됩니다.

소유권과 순서는 능력 정보가 갱신되어도 유지됩니다.

## 능력 감지

| 드라이버 | 근거 |
| --- | --- |
| OpenAI API | `/models` 메타데이터와 잘 알려진 reasoning 모델 이름 |
| LM Studio | `/api/v1/models`의 `capabilities.reasoning.allowed_options` 우선 |
| NNUI Server | `/v1/models` 메타데이터와 잘 알려진 reasoning 모델 이름. 실제 옵션 처리는 llama.cpp 모델·빌드에 따름 |

감지 결과는 설정에서 언제든 수동으로 덮어쓸 수 있습니다. 모델마다 **추론 전달 방식**을 **API** 또는 **시스템 프롬프트**로 고릅니다(관리자, 서빙 모델만). 서버가 옵션 목록을 제공하지 않는 모델에서 **API**를 고르면 `off`·`minimal`·`low`·`medium`·`high`·`xhigh`·`max`를 강제로 전송해 볼 수 있으며(`reasoningForceApi`), 이때도 채팅의 추론 선택기에는 대체 값이 아니라 이 모델에 만든 템플릿만 표시됩니다. 이 설정은 재감지에도 유지되다가 서버가 실제 옵션을 알려 주면 그 옵션으로 대체됩니다. 서버가 받아들이지 않는 값은 요청 오류가 될 수 있습니다. alias의 reasoning 능력은 실제 기반 연결을 따르며, 기반을 바꾸거나 다시 감지해도 올바르게 갱신됩니다. 오래된 설치라면 모델을 다시 감지하고 저장해 레거시 메타데이터를 갱신하세요.

### 서버 옵션의 해석

서버가 알려준 옵션은 템플릿 편집기의 **API로 전송할 값** 자동완성 후보로만 쓰입니다. 템플릿의 값은 매핑 없이 입력한 그대로 전송됩니다(추론 전달 방식이 API일 때만).

## 이전 추론 전달 (생각 기록 기억하기)

이전 assistant 응답의 `reasoning_content`를 다음 요청에 포함할지는 관리자가 `설정 > 모델`에서 모델마다 정합니다. 기본값은 꺼짐이며, 서버가 요청이 아니라 모델 설정을 기준으로 적용합니다. 별칭은 따로 정하지 않으면 실행 중인 기반 모델의 값을 따릅니다. 컨텍스트 사용량 추정도 선택한 모델의 값을 따릅니다.

## 시스템 프롬프트 편집

시스템 프롬프트는 세 단계로 정해지며, 위쪽이 아래쪽을 덮어씁니다.

| 단계 | 편집 위치 | 범위 |
| --- | --- | --- |
| 채팅별 프롬프트 | 입력창 Reasoning 메뉴의 **시스템 프롬프트 편집하기** | 이 채팅의 모델·프리셋 조합 (`conversations.system_prompt_overrides`, 마이그레이션 26) |
| 내 시스템 프롬프트 | `설정 > 모델` | 내 계정의 모델별 값 (`preferences.modelSystemPrompts`) |
| 서버 기본 시스템 프롬프트 | `설정 > 모델` (관리자, alias는 소유자) | 모든 사용자 |

- 채팅별 프롬프트 창은 선택한 추론 프리셋이 적용된 전체 시스템 프롬프트(내 시스템 프롬프트 또는 서버 기본값에 템플릿 프롬프트를 합친 결과)를 보여 주고 편집하게 합니다. 저장하면 그 채팅에만 적용되고 채팅과 함께 저장됩니다.
- 그 채팅에서 **새 채팅**을 열면 채팅별 프롬프트가 그대로 이어집니다. 페이지를 새로 불러왔을 때만 새 채팅이 설정값(내 시스템 프롬프트, 없으면 서버 기본값)으로 시작합니다. 저장된 채팅을 다시 열면 그 채팅의 프롬프트가 복원됩니다.
- 내 시스템 프롬프트는 서버 기본값 자리를 대신하며, 프리셋 템플릿은 그 위에 그대로 합쳐집니다. 비우면 서버 기본값을 씁니다.
- 별칭 모델은 누구나 편집할 수 있습니다. 서빙 모델은 관리자가 **시스템 프롬프트 편집 허용**을 켠 경우에만 일반 사용자가 내 시스템 프롬프트와 채팅별 프롬프트를 쓸 수 있고, 꺼져 있으면 일반 사용자에게는 서버 기본 시스템 프롬프트 값도 전달되지 않습니다. 관리자는 항상 두 입력칸을 모두 봅니다. 서버도 같은 조건으로 저장과 적용을 확인합니다.
- 이전 버전에서 프리셋 없이 저장한 계정별 프롬프트는 처음 읽을 때 내 시스템 프롬프트로 옮겨집니다. 프리셋별로 저장했던 값은 더 이상 쓰이지 않습니다.
- **기본값으로 되돌리기** 후 저장하면 채팅별 프롬프트가 지워집니다.

## 생각 태그

서버가 생각과 답변을 나누지 못하면 `<think>…</think>` 같은 태그가 답변 안에 남거나, 반대로 답변까지 전부 생각(`reasoning_content`)으로 들어와 최종 출력이 비는 경우가 있습니다. NeuralNetUI는 두 스트림을 모두 모델별 **생각 태그** 쌍으로 다시 나눕니다.

- 기본 쌍: `<think>`…`</think>`, `<thinking>`…`</thinking>`, `<|channel>thought`…`<channel|>`. 관리자가 `설정 > 모델`에서 서빙 모델마다 쌍을 추가·삭제(최대 12쌍, 각 64자)하거나 기본값으로 되돌릴 수 있습니다. 모두 지우면 서버가 보낸 그대로 씁니다. 별칭은 실행 중인 기반 모델의 태그를 씁니다.
- 태그 앞뒤에 공백이나 줄바꿈이 없어도 인식하며(`<think>abcd</think>hello` → 생각 `abcd`, 답변 `hello`), 스트리밍 중 청크 경계에서 잘린 태그도 이어 붙여 찾습니다. 태그 바로 뒤의 공백은 버립니다.
- **크로스로 허용하기**(모델별 토글, 기본 꺼짐)를 켜면 어느 시작 태그로 연 생각이든 목록의 어느 끝 태그로도 닫습니다. 예를 들어 `<think>`로 열고 `<channel|>`로 닫는 모델도 나눌 수 있습니다. 별칭은 기반 모델의 값을 따릅니다.
- 답변 스트림에서는 (크로스 허용이 꺼져 있으면) 시작 태그부터 그 쌍의 끝 태그까지가 생각입니다. 생각 스트림에서는 어느 쌍이든 끝 태그가 나오면 그 뒤가 답변입니다. 짝이 맞지 않는 태그는 지웁니다.
- 대화 제목·요약 같은 하네스 생성에도 같은 규칙을 적용합니다.

## 표시

- 추론 생성 중에는 최근 내용이 약 5줄 높이로 스트리밍됩니다.
- 생각하는 동안에는 `n초 동안 생각 중`(1분이 넘으면 `n분 n초 동안 생각 중`)으로 시간이 계속 늘어나며, 바뀐 숫자는 아래에서 위로 굴러 올라오며 살짝 튀듯 자리 잡습니다(9에서 0으로 넘어갈 때도 같음). 완료되면 `n초 동안 생각함`/`Thought for …`으로 바뀝니다. 도구 호출을 사이에 둔 여러 라운드의 생각은 한 블록으로 합쳐지며, 진행 중에는 끝난 라운드의 시간에 현재 라운드의 경과 시간을 더해 셉니다. 라운드가 끝나거나 프롬프트 처리로 넘어갈 때도 화면의 숫자는 줄어들지 않고 늘어나기만 하며, 라운드가 끝난 시간은 실시간 표시와 같은 시계(단계 시작 시각 기준)로 올림해 기록합니다.
- 프롬프트 처리 중에는 그 자리에 항상 `n초 동안 프롬프트 처리 중`으로 경과 시간이 표시됩니다. 처리가 여러 단계로 나뉘면 단계마다 새로 셉니다(합산하지 않음).
- 개인 `설정 > 모양 > 생각 시간 표시`의 두 토글(기본값 모두 켜짐)은 따로 켜고 끕니다. 각 부분은 상태에 따라 `… 중`/`…함`으로 바뀝니다.
  - **프롬프트 처리 시간 같이 보이기**: 생각 블록에 `1분 13초 동안 생각 중 (30초 동안 프롬프트 처리함)`처럼 그 블록에 속한 프롬프트 처리 시간을 함께 표시합니다.
  - **생각 시간에 프롬프트 처리 시간 합산해서 보이기**: 생각 시간에 프롬프트 처리 시간을 더해 표시합니다.
  - 도구 호출 뒤 다음 프롬프트를 처리하는 동안(아직 답변 본문이 나오지 않은 경우) 위의 생각 블록도 함께 갱신됩니다. 합산이 켜져 있으면 생각 시간과 괄호 안 프롬프트 처리 시간이 모두 늘어나고, 꺼져 있으면 괄호 안 프롬프트 처리 시간만 늘어납니다.
- 응답 아래 토큰 속도에 마우스를 올리면 첫 토큰 도착 시간과 함께 프롬프트 처리, 생각, 도구 사용, 최종 응답까지 걸린 시간의 합계가 표시됩니다.
- 모든 추론 관련 아이콘은 전구(Lightbulb)이며, 추론 폴딩은 왼쪽 선 없이 오른쪽/아래 방향 셰브런을 씁니다.
- 실시간 추론 영역은 전사와 별개로 자동 추적을 멈추고 재개할 수 있습니다.

## 프리셋 설명

`설정 > 모양`의 **추론 설명 표시**를 켜면 채팅 선택기에 각 강도의 설명이 함께 보입니다. 강도별 설명은 직접 덮어쓸 수 있고, 비워두면 현재 언어의 기본 문구로 되돌아갑니다. 따라서 언어를 바꿔도 손대지 않은 설명은 그대로 읽을 수 있습니다.

## 기본 추론 강도

Reasoning 선택기 하단의 **기본으로 사용**으로 계정별 기본 강도를 저장합니다. 저장하지 않았으면 모델의 템플릿 목록 맨 위 항목이 기본으로 선택됩니다. alias의 기반 모델은 이제 Reasoning 선택기가 아니라 모델 선택기에서 고릅니다([모델](models.md#커스텀-모델-alias) 참고).
