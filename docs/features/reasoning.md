# Reasoning

## 프리셋 종류

`설정 > 추론`에서 모델별 Reasoning 프리셋을 관리합니다.

| 종류 | 동작 |
| --- | --- |
| **Built-in** | 선택한 값을 OpenAI 호환 요청의 `reasoning_effort`로 전달합니다 |
| **Custom template** | 선택한 내장 effort를 전달한 뒤, 템플릿 내용을 모델/alias 시스템 프롬프트와 조합합니다 |

커스텀 템플릿의 시스템 프롬프트는 세 가지 방식으로 모델 프롬프트와 합쳐집니다.

| 모드 | 결과 |
| --- | --- |
| `replace` | 모델 프롬프트를 템플릿으로 대체 |
| `prepend` | 템플릿을 앞에 붙임 |
| `append` | 템플릿을 뒤에 붙임 (기본) |

커스텀 프리셋은 만든 사람에게만 보이고, 소유권과 순서는 능력 정보가 갱신되어도 유지됩니다.

## 능력 감지

| 드라이버 | 근거 |
| --- | --- |
| OpenAI API | `/models` 메타데이터와 잘 알려진 reasoning 모델 이름 |
| LM Studio | `/api/v1/models`의 `capabilities.reasoning.allowed_options` 우선 |

감지 결과는 설정에서 언제든 수동으로 덮어쓸 수 있습니다. alias의 reasoning 능력은 실제 기반 연결을 따르며, 기반을 바꾸거나 다시 감지해도 올바르게 갱신됩니다. 오래된 설치라면 모델을 다시 감지하고 저장해 레거시 메타데이터를 갱신하세요.

### 서버 옵션의 해석

프리셋은 서버가 알려준 옵션을 그대로 씁니다.

| 서버가 알려준 값 | 표시 |
| --- | --- |
| `off` / `none` | Fast |
| `on` | Thinking (강도 단계 없음) |
| 지원 정보 없음 | Default |

Chat Completions 경로에서는 `off`/`on`이 각각 `none`/`medium`으로 매핑되고, 지원하지 않는 프리셋 값은 요청에서 생략됩니다.

Qwen3.8의 화면상 **Extra High**는 실제 서버가 허용하는 API 값인 `xhigh`로 전송됩니다.

## 이전 추론 전달

입력창의 Reasoning 메뉴에서 이전 assistant 응답의 `reasoning_content`를 다음 요청에 포함할지 고를 수 있습니다. 이 토글은 즉시 반영되어 컨텍스트 사용량 추정에도 반영됩니다.

## 표시

- 추론 생성 중에는 최근 내용이 약 5줄 높이로 스트리밍됩니다.
- 완료되면 실제 측정한 소요 시간이 `Thought for …` 또는 `… 동안 생각함`으로 표시됩니다.
- 모든 추론 관련 아이콘은 전구(Lightbulb)이며, 추론 폴딩은 왼쪽 선 없이 오른쪽/아래 방향 셰브런을 씁니다.
- 실시간 추론 영역은 전사와 별개로 자동 추적을 멈추고 재개할 수 있습니다.

## 프리셋 설명

`설정 > 모양`의 **추론 설명 표시**를 켜면 채팅 선택기에 각 강도의 설명이 함께 보입니다. 강도별 설명은 직접 덮어쓸 수 있고, 비워두면 현재 언어의 기본 문구로 되돌아갑니다. 따라서 언어를 바꿔도 손대지 않은 설명은 그대로 읽을 수 있습니다.

## 기본 추론 강도

Reasoning 선택기 하단의 **기본으로 사용**으로 계정별 기본 강도를 저장합니다. 관리자는 옆의 **전체 적용**으로 워크스페이스 기본값을 정하고 모든 계정에 반영할 수 있습니다.
